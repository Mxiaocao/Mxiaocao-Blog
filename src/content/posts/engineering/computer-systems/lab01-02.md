## 1. 实验环境搭建

### 1.1 WSL

WSL (Windows Subsystem for Linux) 是微软提供的Windows下运行Linux环境的技术，使用户无需安装双系统或传统虚拟机，也能在Windows中使用Linux命令、工具和开发环境



#### 1.1.1 为什么需要 Linux 环境

我们的电脑通常是 “Windows $\rightarrow$ 用户程序”，比方我们平时直接打开Obsidian、微软大战代码(bushi)等

但是计算机系统课程需要研究gcc、gdb、Linux程序调用、文件权限、汇编、程序运行过程等，而这些东西在 Linux 环境下更加方便
换句话来说，普通用户只关注“打开程序 $\rightarrow$ 点击按钮 $\rightarrow$ 程序运行”，但是计算机系统课程关注“c代码 $\rightarrow$ 编译器 $\rightarrow$ 汇编代码 $\rightarrow$ 机器指令 $\rightarrow$ CPU执行 $\rightarrow$ 内存变化”

于是，我们需要从 Windows 电脑转到 Linux 实验环境

而下面是不同方式之间的比对

| 方法   | 途径                                                  | 优点           | 缺点                |
| ------ | ----------------------------------------------------- | -------------- | ------------------- |
| 双系统 | 开机 $\rightarrow$ 选择 Windows or Ubuntu Linux       | 性能最好       | 切换麻烦，占空间    |
| 虚拟机 | Windows $\rightarrow$ Vmware $\rightarrow$ Ubuntu     | 完整Linux环境  | 占CPU、内存         |
| WSL2   | Windows $\rightarrow$ WSL2 $\rightarrow$ Ubuntu Linux | 轻量，开发方便 | 和完整Linux仍有区别 |

对于这门课，我们只需要gcc、gdb、Linux命令和文件操作等，而不需要模拟完整显卡、Linux桌面环境或大型服务器环境等，所以WSL2足够



#### 1.1.2 WSL1 与 WSL2 区别

|            | WSL1                                                         | WSL2                                                         |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| Linux内核  | 没有真正Linux内核                                            | 真正Linux内核                                                |
| 速度       | 快                                                           | 较快                                                         |
| 兼容性     | 一般                                                         | 强                                                           |
| Docker支持 | 不好                                                         | 支持                                                         |
| 资源占用   | 低                                                           | 稍高                                                         |
| 本质       | Linux程序 $\rightarrow$ 系统调用转换 $\rightarrow$ Windows （翻译） | Linux程序 $\rightarrow$ Linux内核 $\rightarrow$ Windows硬件（运行） |

WSL2 使用真正的 Linux 内核，并运行在 Windows 提供的轻量虚拟化环境中



#### 1.1.3 第一次进入Ubuntu

当我们打开Windows Terminal，输入`wsl`，就会有类似`username@computer:~$`，我们把这个拆开，就有：

```
username  ->  当前用户
@computer  ->  主机名
:  ->  仅仅是分隔符
~  ->  当前用户的Home目录 （比方说 cd ~ 等价于 cd /home/mxiaocao）
$  ->  普通用户 （root用户则是#）
```

例如 `mxiaocao@LAPTOP-N5V09A3E:~$`

当然，我们还有一些WSL常用管理命令

| 作用            | 指令                |
| --------------- | ------------------- |
| 查看Linux发行版 | wsl -l -v           |
| 关闭WSL         | wsl --shutdown      |
| 更新WSL         | wsl --update        |
| 查看当前版本    | wsl --version       |
| 进入指定Ubuntu  | wsl -d Ubuntu-24.04 |



#### 1.1.4 Windows 访问 Linux

Linux文件在哪里呢？

比如你在Ubuntu里面输入`pwd`，可能看到`/home/mxiaocao`，这个目录属于Linux，完整结构为

```
Linux系统
|
/
│
├── home
│    └── username
│
├── bin
├── usr
├── etc
```
这里面的`/`叫 Linux根目录，类似于Windows的`C:\`

那我们在 Windows 怎么看 Linux 文件呢？

打开 Windows 文件管理器，地址栏输入 `\\wsl$\Ubuntu-24.04`，输入之后，你会看到

```
Ubuntu-24.04
├── home
├── usr
├── bin
├── etc
```
这其实就是你的Linux文件系统，而对于同一份文件，会有

| 系统      | 地址                                          |
| ------- | ------------------------------------------- |
| Windows | `\\wsl$\Ubuntu-24.04\home\mxiaocao\hello.c` |
| Linux   | /home/mxiaocao/hello.c                      |

为什么地址是`\\wsl$`呢？

拆开`\\wsl$\Ubuntu-24.04`，分成

```
\\  -> 网络访问格式

wsl$  -> Windows提供的WSL共享入口

Ubuntu-24.04  -> 你的Linux发行版名字
```
这类似访问局域网电脑通过`\\192.168.1.10`,WSL也伪装成一个网络共享，所以Windows认为这是一个网络位置，当然，实际上这是本机里的Linux文件系统
(补充：`\\wsl$` 是 Windows 提供的 WSL 文件系统访问入口，虽然形式像网络路径，但实际访问的是本机 WSL 文件系统)



#### 1.1.5 Linux访问Windows

Linux访问Window更加常用

在你的Windows里`C:\Users\Mxiaocao`，在Linux里面则对应`/mnt/c/Users/Mxiaocao`

Linux里面有一个目录`/mnt`，它是专门用来挂载外部设备，比如
```
/mnt
 |
 |
 ├── c
 |
 ├── d
 |
 └── e
```
对应windows中的c盘、d盘和e盘

Windows盘符映射则是

| Windows | Linux  |
| ------- | ------ |
| C盘     | /mnt/c |
| D盘     | /mnt/d |
| E盘     | /mnt/e |

那为什么会有/mnt呢？

mnt全名就是mount，意为挂载。由于Linux设计思想就是所有设备都是文件，所以说Windows C盘就被挂载到Linux目录`/mnt/c`，U盘被挂载到`/mnt/usb`，网络盘被挂载到`/mnt/network`（注意：严谨来说，我们不能说硬盘就是/mnt/c，而是要说“挂载”）

现在举个例子，假设windows桌面（C:\Users\Mxiaocao\Desktop）上有`hello.c`，那么在Linux里面，你`cd /mnt/c/Users/Mxiaocao/Desktop`后，然后`ls`查看，就会看到`hello.c`，后面直接`gcc hello.c -o hello`，就能够实现Linux编译Windows里的文件

反过来也一样，比如你在Linux里 `cd ~` `touch test.c` 创建，那么此时文件地址为`/home/mxiaocao/test.c`，我们用windows打开`\\wsl$\Ubuntu-24.04\home\mxiaocao`就能看到`test.c`

当然我们还是要注意一点，虽然`/mnt/c`可以用，但是对于gcc大量编译、git项目、Linux权限实验等，还是更推荐`/home/你的用户名`，因为Linux文件系统性能更好，例如，我们会推荐`/home/mxiaocao/project`而不是`/mnt/c/project`



### 1.2 GCC 

前面我们解决的是在哪里运行程序，这里我们开始解决程序是怎么从代码变成计算机能执行的东西

hello.c $\xrightarrow{gcc}$ hello $\rightarrow$ CPU执行



#### 1.2.1 什么是GCC

GCC (GNU Compiler Collection)，意为GNU编译器集合，它不是一个简单的“c转exe工具”，而是一整套编译工具（gcc本身主要作为编译驱动程序，负责调用或协调预处理器cpp、编译器cc1、汇编器as和链接器ld完成整个编译过程），支持C/C++、Go等语言

在我们的课程中，我们主要使用gcc编译c程序



#### 1.2.2 为什么需要GCC

计算机不能直接理解C语言，比方说我们写一个hello world程序，人能看懂，但是CPU不认识main、return、printf这些，它只认识01010101，所以需要“hello.c $\rightarrow$ 编译器 $\rightarrow$ 机器语言 $\rightarrow$ CPU执行”



#### 1.2.3 程序运行完整过程

hello.c $\xrightarrow{预处理}$ hello.i $\xrightarrow{编译}$ hello.s $\xrightarrow{汇编}$ hello.o $\xrightarrow{链接}$ hello $\xrightarrow{运行}$ CPU执行

```
.c 源代码 (C source file)
.i 预处理后的c代码 (Intermediate file)
.s 汇编代码 (Assembly source file)
.o 目标文件 (Object file)
hello 可执行文件 (Executable)
```

**预处理（Preprocessing）**
输入`hello.c`处理，预处理器会展开头文件、处理宏、删除注释，生成`hello.i`
`gcc -E hello.c -o hello.i`，其中`-E`表示“只进行预处理，预处理完成后停止”

比如`#define MAXN 100`,`int a = MAXN`，预处理后变成`int a = 100`

**编译（Compilation）**
输入`hello.i`输出`hello.s`，把c语言转换成汇编语言
`gcc -S hello.i -o hello.s`，其中`-S`表示“编译到汇编语言后停止，不在进行汇编和链接”

比如，a+b可能变成mov add sub

**汇编（Assembly）**
输入`hello.s`输出`hello.o`，把汇编语言转换成机器码
`gcc -c hello.s -o hello.o`，其中`-c`表示“编译、汇编得到目标文件，但不执行最终链接”

为什么此时还不能运行？因为里面可能缺少函数，比方说`printf`这个函数，又不是你写的，是人家写在c标准库的，所以需要下一步

说官方点，就是此时得到的 `.o` 是目标文件，里面虽然已有机器代码，但还没有完成符号解析、重定位以及与其他目标文件和库的链接，因此通常不能直接运行

**链接（Linking）** 
输入`hello.o`，链接器把你的代码+系统库+其他目标文件合并，生成`hello`
`gcc hello.o -o hello`，然后`./hello`即可运行
(补充：Linux可执行文件通常没有`.exe`后缀，所以不要写成`hello.exe`)

我们平时直接`gcc hello.c -o hello`一条命令生成程序，但实际上，gcc自动帮我们完成了这四个阶段



#### 1.2.4 gcc常用参数

| 参数  | 作用                      |
| ----- | ------------------------- |
| -E    | 只进行预处理              |
| -S    | 编译成汇编文件后停止      |
| -c    | 生成目标文件，不链接      |
| -o    | 指定输出文件名            |
| -g    | 加入gdb调试信息           |
| -v    | 显示gcc编译过程等详细信息 |
| -O    | 开启优化                  |
| -Wall | 打开较多常见编译警告      |



**① -o**

作用：指定输出文件名

例如 `gcc hello.c -o hello`，意思是编译`hello.c`生成`hello`，当然，如果直接`gcc hello.c`则默认生成`a.out`

(补充：由于历史原因Assembler Output，现在默认这个a.out)

**② -g**

作用：调试，和GDB有关

例如，`gcc -g hello.c -o hello`后，GDB就能看到函数main、第十行代码等，也就是说 -g 给可执行文件加入调试信息

**③ -m32**

作用：生成32位程序

例如，`gcc -m32 hello.c -o hello`，生成32位可执行程序

（补充：我们的课程需要它是因为相较于64位程序，我们更容易观察栈、指针、内存分布等）



#### 1.2.5 实际操作

创建`hello.c`，`gcc hello.c -o hello`编译，`ls`查看，出现

```
hello
hello.c
```

然后`./hello`运行，输出`hello world`

为什么运行要加`./`呢？

因为当前目录默认不在PATH中，而加`./`意思是执行当前目录下`hello`



### 1.3 GDB

前面 GCC 解决的是：

> **程序怎么从 C 代码变成 CPU 能执行的程序**

这里 GDB 解决的是：

> **程序已经能运行了，但是运行结果不对，我们怎么知道它到底在哪一步出了问题？**



#### 1.3.1 什么是GDB

GDB（GNU Debugger）是 GNU 提供的程序调试工具，用来观察程序在运行过程中发生了什么，从而帮助我们定位程序中的错误

GDB 可以让程序在指定位置暂停、逐条执行代码、查看变量的值，也可以在调试过程中修改变量的值。



#### 1.3.2 GDB的基本调试流程

```markdown
编译程序（test.c => gcc -g => test）
   ↓
启动 GDB（gdb test）
   ↓
查看代码
   ↓
设置断点
   ↓
运行程序
   ↓
程序停在断点
   ↓
单步执行
   ↓
查看变量
   ↓
继续运行
```



#### 1.3.3 为什么编译时要加-g

我们`gcc test.c -o test`时，虽然程序也可以运行，但是我们还没有加入完整的调试信息，调试时，我们一般用`gcc -g test.c -o test`，其中`-g`表示在生成的可执行文件中加入调试信息，这样GDB才能知道这段机器指令来自test.c的第几行，这个位置对应哪个函数，这个变量叫什么名字等等，也就是说`-g`建立了类似`机器指令`$\leftrightarrow$`源代码行号、变量、函数`这样的对应关系，因此`gcc -g test.c -o test`可以理解为“生成一个方便GDB调试的可执行程序”

我们首先`gcc -g test.c -o test`，然后`gdb test`即可进入GDB



#### 1.3.4 启动GDB

一般我们用`gdb test`，意思是启动GDB+载入test程序，进入后会看到`(gdb)`，此时，我们输入的就不是Linux命令，而是GDB命令



#### 1.3.5 GDB命令

| 完整命令 | 简写 | 作用               |
| -------- | ---- | ------------------ |
| list     | l    | 查看代码           |
| break    | b    | 设置断点           |
| run      | r    | 运行程序           |
| next     | n    | 下一行，不进入函数 |
| step     | s    | 下一行，进入函数   |
| print    | p    | 查看变量           |
| continue | c    | 继续运行           |
| quit     | q    | 退出GDB            |



**① list**

作用：查看源代码

例如：

- `list`显示当前位置附近的源代码

- `list 15`查看第15行附近的代码

- `list add`查看`add`函数的代码

`list`可以简写成`l`

**② break**

作用：设置断点，让程序运行到指定位置时暂停

例如：

- `break 15`表示在第15行设置断点

- `break add`表示在`add`函数处设置断点

`break`可以简写成`b`

（补充：断点就是告诉程序“运行到这里先停一下”，这样我们才能查看此时变量的值和程序状态）

**③ info break**

作用：查看当前设置的断点

例如：

- `info break`会显示断点编号、位置、是否启用等信息

当然，也可以简写成 `info b`

**④ run**

作用：运行被调试程序

例如：

- `run`会让程序从头开始运行，如果遇到断点，就会停止

`run`可以简写成`r`

（补充：如果没有设置断点，那么程序通常会直接运行到结束）

**⑤ print**

作用：查看变量或者表达式当前的值

例如：

- `print i`查看变量`i`当前的值

- `print sum`查看`sum`的值

`print`可以简写成`p`

除此之外，还可以直接通过`print i = 100`修改变量：表示在调试过程中把`i`修改成100

**⑥ next**

作用：单步执行下一条源程序语句，但是**遇到函数调用不会进入函数内部**

例如，当前代码是`result = add(50);`，执行`next`，GDB会直接执行完整个`add(50)`，然后停在下一行

`next`可以简写成`n`

可以理解为，`next` 执行下一行，但不进入函数

**⑦ step**

作用：单步执行下一条源程序语句，如果遇到函数调用，**会进入函数内部**

例如，`result = add(50);`，执行`step`，程序会进入`add()`函数里面继续调试

`step`可以简写成`s`

可以理解为，`step` 执行下一行，并进入函数

所以`next`和`step`最大的区别就是：

```
next：不进入函数（step over）
step：进入函数（step into）
```

**⑧ continue**

作用：从当前位置继续运行程序

例如，`continue`后，程序会一直运行，直到遇到下一个断点或程序运行结束

`continue`可以简写成`c`

（补充：如果你已经在断点处停下来了，又不想一行一行执行，就可以直接用`continue`）

**⑨ finish**

作用：执行完当前函数，然后返回到调用这个函数的位置

例如现在通过`step`进入了`add()`，如果不想继续一行一行看这个函数，可以`finish`。GDB会把`add()`剩余部分执行完，然后回到调用`add()`的地方。

可以理解为，`finish` = 把当前函数跑完并退出这个函数

**⑩ info**

作用：查看调试过程中的各种状态信息

例如，`info break`查看断点。

除此之外，`info`还可以和其他参数组合使用

**⑪ help**

作用：查看GDB帮助信息

例如：

- `help`查看GDB命令帮助

- `help break`专门查看`break`命令的使用方法。

（补充：GDB命令很多，不需要全部死记，不会的时候可以直接用`help`查）

**⑫ quit**

作用：退出GDB

`quit`可以简写成`q`

如果当前被调试程序还没有结束，GDB可能会询问`Quit anyway? (y or n)`，输入`y`即可退出。

**⑬ `bt`**

作用：查看当前的函数调用栈

例如，`bt`后，可能看到

```
#0 add(...)
#1 main(...)
```

说明当前正在`add()`函数里，而`add()`是由`main()`调用的



## 2. Linux基础

Linux 整体结构是"用户 $\rightarrow$ Shell $\rightarrow$ 系统调用 $\rightarrow$  Linux 内核 $\rightarrow$ 硬件"

### 2.1 Linux是什么

首先要明确 Linux != Ubuntu，Linux本质是一个操作系统内核，而Ubuntu是基于Linux内核的一种发行版

Linux由芬兰大学生 Linus Torvalds 在 Minix 基础上开发（受到MINIX的启发，并且最初在MINIX环境中进行开发），并于1991年发布Linux 0.02版本
发展关系大致为 "Multics（早期大型操作系统项目） $\rightarrow$ UNIX $\rightarrow$ Minix $\rightarrow$ Linux"



### 2.2 Linux特点

#### 2.2.1 多任务、多用户

Linux设计之初就是用户A、用户B、用户C同时使用系统，所以我们日常也可以用`who`来查看登录用户



#### 2.2.2 开放源代码

Linux采用GPL开源思想，允许使用、修改与分发



#### 2.2.3 网络功能强

Linux天生适合服务器，所以有大量服务器运行Linux，比如Web服务器、云服务器以及数据库服务器等



### 2.3 Linux系统结构

#### 2.3.1 用户层

平时输入`ls`，这个就属于用户发出的请求，但是Linux不知道你输入了什么，中间需要Shell



#### 2.3.2 Shell层

Shell是用户和Linux内核之间的翻译员，比如我们输入`ls`，实际过程就是“输入ls $\rightarrow$ Shell解析 $\rightarrow$ 调用系统接口 $\rightarrow$ Linux内核 $\rightarrow$ 访问文件系统 $\rightarrow$ 返回结果”

所以说，Shell不是linux内核，它只是命令解释器

当然Shell不是只有一种

| Shell | 说明        |
| ----- | ----------- |
| bash  | Linux最常用 |
| sh    | 早期Shell   |
| zsh   | 功能更丰富  |



#### 2.3.3 Linux内核

Kernel负责CPU调度、内存管理、文件管理和设备管理

比如，你执行`cat hello.txt`，本质上是“cat $\rightarrow$ 请求内核 $\rightarrow$ 内核读取磁盘 $\rightarrow$ 返回数据 $\rightarrow$ 显示“



### 2.4 Shell基础

当我们打开Ubuntu，看到`mxiaocao@computer:~$`这个就是Shell，我们可以进行拆解，当然这个前面也有讲

```
mxiaocao  ->  用户名
LAPTOP  ->  主机名
~  ->  当前用户Home目录
$  ->  普通用户 （root显示#）
```



### 2.5 Linux命令基本格式

Linux命令通常为`command [option] [argument]`，一一对应即为`命令 [选项] [参数]`

比如，`ls -l /home`

[**注**]：[]表示可选，例如我们`ls`也可以，`ls -l`也可以



### 2.6 文件操作命令

| 命令  | 作用         | 全称                    |
| ----- | ------------ | ----------------------- |
| pwd   | 查看当前目录 | print working directory |

### 2.7 Linux文件系统

#### 2.7.1 Linux文件系统和Windows文件系统区别

Windows采用盘符式结构，例如

```
C:\
D:\
E:\
```

每个盘都是一个独立入口

Linux采用树形目录结构，最高层`/`称为根目录，所有文件都从这里开始，例如

```
/
 |
 |--- home
 |
 |--- usr
 |
 |--- etc
 |
 |--- dev
```

因为Linux设计思想就是所有资源都看成文件，包括硬盘、U盘等都通过目录挂载

例如我们的Windows C盘在WSL变成`/mnt/c`，意思是Windows C盘挂载到Linux目录`/mnt/c`上



#### 2.7.2 Linux主要目录介绍

| 目录  | 作用     | 解释      |
| ----- | -------- | --------- |
| /     | 根目录   | Linux起点 |
| /home | 用户文件 | 家目录    |
| /bin  | 基本命令 | binary    |
| /usr  | 用户程序 | 软件资源  |
| /etc  | 配置文件 | 系统设置  |
| /tmp  | 临时文件 | temporary |
| /dev  | 设备文件 | device    |

**① /（根目录）**

是Linux整个文件系统的起点，例如，`cd /`，则进入

```
/
├── home
├── bin
├── etc
├── usr
```

类似Windows的`C:\`

**② /home（用户目录）**

存放普通用户个人文件

比方说用户是mxiaocao，那么/home/mxiaocao就是你的家目录，也就是`~`

`cd ~` 等价于 `cd /home/mxiaocao`

**③ /bin**

bin (binary)，意思是二进制可执行程序，里面存放Linux基本命令

```
/bin
├── ls
├── cp
├── mv
├── rm
└── cat
```

所以，当我们输入`ls`，系统实际上运行`/bin/ls`

**④ /usr**

usr (Unix System Resource)，主要存放用户程序和资源

```
/usr
├── bin
├── lib
└── share
```

很多安装的软件都会放在`/usr/bin`，比如gcc可能在`/usr/bin/gcc`

**⑤ /etc**

存放系统配置文件

```
/etc
├── passwd
├── hosts
├── ssh
└── environment
```

例如用户信息可能放`/etc/passwd`，网络配置可能放`/etc/hosts`

**⑥ /tmp**

temporary，临时文件，通常可以删除或者重启可能清空

**⑦ /dev**

device，设备文件



#### 2.7.3 绝对路径和相对路径

- **绝对路径**

  从根目录`/`开始，例如`/home/mxiaocao/project`

- **相对路径**

  从当前目录开始，比如`pwd`，输出`/home/mxiaocao`，里面有`project`，我们就直接`cd project`

- **特殊路径符号**

  **.** **当前目录**

  例如`./hello`表示执行当前目录的hello

  **..** **上一级目录**

  例如当前位置`/home/mxiaocao/project`，执行`cd ..`，进入`/home/mxiaocao`

  **~** **Home目录** 

  例如 `cd ~`，进入`/home/mxiaocao`



### 2.8 Linux文件权限

#### 2.8.1 为什么Linux需要权限

Linux是一个多用户操作系统，也就是说同一台Linux服务器可能有用户A、用户B、用户C。如果没有权限，用户A可以随便删除用户B文件，这是不安全的，所以Linux规定，每个文件都有文件所有者、用户组、其他用户三类权限



#### 2.8.2 查看文件权限

使用`ls -l`，显示`-rwxr-xr-x 1 mxiaocao users 1234 hello`

重点看前面的`-rwxr-xr-x`

```
- | rwx | r-x | r-x
↑    ↑      ↑      ↑
类型 用户  用户组  其他用户
```

- **文件类型**

  | 符号 | 含义     |
  | ---- | -------- |
  | -    | 普通文件 |
  | d    | 目录     |
  | l    | 链接文件 |

  例如，目录是`drwxr-xr-x`

- **rwx权限**

  1. **r:read**

     读权限，表示可以查看内容

     例如`cat hello.c`需要r权限

  2. **w:write**

     写权限，表示可以修改文件内容

     例如`vim hello.c`需要w权限

  3. **x:execute**

     执行权限，表示可以运行文件

     例如`./hello`需要x权限

举例，`-rwxr-xr--`拆成`-` `rwx` `r-x` `r--`

文件所有者：rwx，可读可写可执行

用户组：r-x，可读可执行不能写

其他用户：r--，可读不能写不能执行



#### 2.8.3 chmod修改权限

格式为`chmod 权限 文件名`，比如`chmod 777 hello.c`

那么这个777是什么意思呢？

Linux权限可以用数字表示
| 权限 | 数字 |
| ---- | ---- |
| r    | 4    |
| w    | 2    |
| x    | 1    |

所以r+w+x=4+2+1=7
即，777表示用户rwx (7)、用户组rwx (7)、其他rwx (7)，也就是rwxrwxrwx

常用的权限数字有755（程序文件），644（普通文本文件），777（实验中方便使用）



#### 2.8.4 root用户

普通用户`$`，root`#`

root叫超级用户，拥有几乎所有文件访问权限，修改系统配置权限

比如：普通用户是`mxiaocao@ubuntu:~$`，root是`root@ubuntu:~#`
