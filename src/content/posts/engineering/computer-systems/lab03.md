计算机处理的数字、字符和程序，最后都会变成一串 0 和 1。不过，这串二进制到底表示什么，又能进行什么运算，还要看我们怎样解释它。这里就从数制和编码开始，继续看整数、浮点数、字符的表示，以及它们在内存中的存放和运算。

[**注**]：下面涉及具体机器数时，默认采用本文 x86-64 Linux/WSL 环境：一个字节为 8 位，`char`、`short`、`int` 分别占 1、2、4 字节，`long`、`long long` 和对象指针占 8 字节；`float`、`double` 分别采用 IEEE 754 单精度和双精度。涉及教材中的其他格式或 32 位环境时，会另外说明。

## 1. 数制和编码

### 1.1 信息的二进制编码

计算机内部不只是数字，文字、图片、声音最后也需要编码成二进制。二进制只有 0 和 1，硬件可以用两种容易区分的状态表示它们，也方便用逻辑电路处理。

但是，一串 0/1 本身不会告诉我们它是什么。比方说 `01000001`，按无符号整数解释是 65，按 ASCII 字符解释就是 `A`。所以我们还需要知道编码规则。

![同一位串在不同编码规则下表示不同真值](/images/posts/computer-systems/lab03/lab03-01-bit-interpretation.png)

#### 1.1.1 从外部信息到机器中的位串

对于声音这种连续变化的信息，计算机需要先采样，把连续时间上的信息变成离散样本，再量化为有限精度的数值，最后编码成二进制。图片也类似，要把像素的位置、颜色等信息编码保存。由于存储和运算部件的位数有限，机器不能直接容纳任意精细的连续信息。

而到了机器指令这一层，高级语言里的数组、结构体等复杂对象，又会拆成对整数、浮点数和位串的操作。也就是说，数据结构可以很复杂，但是底层每次处理的对象仍然有确定的宽度和格式。

解释一个数值位串，需要同时确定进位计数制、小数点的位置和编码规则。只知道“它是二进制”还不够，比方说 `10000000` 按 8 位无符号整数解释是 128，按 8 位补码整数解释是 -128，按补码定点小数解释则是 -1。

#### 1.1.2 二进制数与 BCD 码

BCD 是 Binary Coded Decimal，用二进制位给十进制数字逐位编码。常见的 8421 BCD 用 4 位表示一位十进制数字，因此只用到 `0000～1001`，`1010～1111` 不作为普通十进制数字使用。

比方说，十进制 59 的普通二进制表示为 `00111011`，但 8421 BCD 表示是 `0101 1001`，前四位表示 5，后四位表示 9。后者是在编码两个十进制数位，不能把整串当成普通二进制数来求值。BCD、整数和 ASCII 数字字符也是三种不同表示，字符 `'5'` 的 ASCII 编码还要到后面的字符部分讨论。

#### 1.1.3 机器数与真值

数学中的数要先按照一定规则编码，才能放进计算机。这个编码后的二进制表示叫作**机器数**；它实际表示的数学数值，叫作**真值**。比方说，真值是 -7，采用 8 位补码后，机器数就是 `11111001`。

同一个真值，采用不同编码，可以得到不同机器数。还是 -7，8 位原码是 `10000111`，反码是 `11111000`，补码是 `11111001`。这些编码怎样得到，放在 1.4 节讲。

反过来，同一个机器数采用不同规则解释，也可能得到不同真值。比方说，`80000000H` 按 32 位 `int` 的补码规则解释是 -2147483648，按 32 位 `unsigned int` 解释则是 2147483648。bit 没变，变的是解释规则。

因此，接下来要依次弄清楚三件事：每一位的位权是多少，小数点放在哪里，以及正负数怎样编码。它们分别对应进位计数制、定点数与浮点数、定点数的编码表示。

### 1.2 进位计数制

对于 r 进制，每一位只能取 `0～r-1`，相邻位的位权相差 r 倍。小数点左边从 $r^0$ 开始，右边从 $r^{-1}$ 开始，这就是按位权展开的依据。二进制、八进制和十六进制的基数分别是 2、8 和 16。

#### 1.2.1 基数、位权与书写形式

对于 $r$ 进制数 $d_n\cdots d_0.d_{-1}\cdots d_{-m}$，它的值为

$$
V=\sum_{i=-m}^{n}d_i r^i,\qquad 0\le d_i<r
$$

这里的 $r$ 是基数，$r^i$ 是第 i 位的位权。同一个数字出现在不同位置，表示的量就不同。

| 进制 | 可用数码 | 常见写法 | C11 中的输出方式 |
| --- | --- | --- | --- |
| 二进制 | 0、1 | $1010_2$、1010B | 自己编写输出函数 |
| 八进制 | 0～7 | $12_8$，C 中写作 `012` | `%o` |
| 十进制 | 0～9 | $10_{10}$、10D | `int` 用 `%d`，`unsigned int` 用 `%u` |
| 十六进制 | 0～9、A～F | $A_{16}$、0AH、`0xA` | `%x` 或 `%X` |

十六进制中的 A～F 依次表示 10～15。这几种写法可以表示同一个值，十六进制常用于缩短机器数的书写长度，并不表示机器内部改成了十六进制运算。

这里还要分清两件事：源码中的数是按什么进制写的，以及 `printf` 最后按什么进制把它打印出来。比方说，写这个表格的时候，我写到`012`的时候很疑惑，于是我去问ai，然后ai告诉我，`012` 是八进制常量，值为十进制的 10；`12` 是十进制常量，值就是 12。`%o`、`%u`、`%x` 或 `%X` 决定输出采用八、十、十六进制，其中 `%X` 用大写字母，`%x` 用小写字母。对于 `int` 类型的十进制输出使用 `%d`，下面统一采用 `unsigned int`，因此使用 `%u`。

而后，为了详细地区别一下这些，我额外写了一个打印函数，加深一下我们的印象

我们的函数有两组功能，第一组把不同写法按十进制输出；第二组固定数值为 12，分别输出二、八、十、十六进制。

```c
#include <stdio.h>

void print_binary(unsigned int value){
    if(value >= 2) print_binary(value/2);

    putchar('0' + value%2);
}

void show_number_bases(void){
    /* 因为C11没有标准的二进制整数字面量，所以我们还要单独按位权构造 1010(2) */
    unsigned int binary = (1U << 3) | (1U << 1);
    unsigned int value = 12U;

    puts("Group 1: different literal forms -> decimal");
    printf("1010(2) -> %u\n", binary); // 10
    printf("012     -> %u\n", 012U);   // 10
    printf("12      -> %u\n", 12U);    // 12
    printf("0xA     -> %u\n", 0xAU);   // 10

    puts("\nGroup 2: the same value 12 -> different output bases");
    printf("binary : ");
    print_binary(value);              // 1100
    putchar('\n');
    printf("octal  : %o\n", value);   // 14
    printf("decimal: %u\n", value);   // 12
    printf("hex    : %X\n", value);   // C
}

int main(void){
    show_number_bases();
    return 0;
}
```

这里使用 C11，因此二进制的 `1010` 通过位权构造（`1U << 3` 得到 8，`1U << 1` 得到 2，然后按位或后得到 10）。因为C11 没有标准的 `0b` 二进制前缀，也没有标准的 `%b` 输出格式，所以用 `print_binary` 递归输出，而数值为 0 时，这个函数也会正确输出 `0`

代码运行结果如下：

![二、八、十、十六进制的输入写法与输出格式对照](/images/posts/computer-systems/lab03/vscode-result-number-bases.png)

第一组中的 `1010(2)`、`012` 和 `0xA` 都表示十进制的 10，而 `12` 表示十进制的 12
第二组的 `1100`、`14`、`12` 和 `C` 则是同一个值在四种进制下的写法。换格式符只改变输出形式，不会把变量里的数值改掉。


#### 1.2.2 十进制整数 $\Rightarrow$ 二进制

先看整数部分：每次除以 2，记下余数，直到商为 0。最后把余数自下而上读出来，就得到二进制数。因为第一次取出的是最低位，所以读取顺序要反过来。

例如，对于$12_{10}$，我们能得到$1100_2$
$$
12 \div 2 = 6\quad 余0\\
6 \div 2 = 3\quad 余0\\
3 \div 2 = 1\quad 余1\\
1 \div 2 = 0\quad 余1\\
\text{余数自下而上}
$$

#### 1.2.3 十进制小数 $\Rightarrow$ 二进制

小数部分正好相反：每次乘以 2，取出整数部分，再拿剩下的小数继续乘。取出的整数按先后顺序排列，就是小数点后的二进制位。也就是“乘 2 取整，自上而下”。

例如，对于$0.75_{10}$，我们能得到$0.11_2$
$$
0.75\times2 = 1.5 \quad 取整数1\\
0.5 \times2 = 1.0 \quad 取整数1
$$

整数和小数分别转换后，再在小数点两边拼起来即可。比方说，$12.75_{10}=1100.11_2$。换成其他 $r$ 进制时，整数部分改成除 $r$ 取余，小数部分改成乘 $r$ 取整。

#### 1.2.4 二进制 $\Rightarrow$ 十进制

反过来，从二进制求十进制值，只需要按位权展开。

二进制小数点左侧：$2^0,2^1,2^2,2^3,\dots$

二进制小数点右侧：$2^{-1},2^{-2},2^{-3},\dots$

例如$1100.11_2$展开得到 $1\times2^3 + 1\times2^2 + 0\times2^1 + 0\times2^0 + 1\times2^{-1} + 1\times2^{-2}$，即$1100.11_2 = 12.75_{10}$

#### 1.2.5 二进制与八进制、十六进制

因为 $8=2^3$、$16=2^4$，所以每 3 位二进制对应 1 位八进制，每 4 位二进制对应 1 位十六进制。以小数点为界，整数部分向左分组，小数部分向右分组，不够的在最外侧补 0。

比方说，$1100.11_2=1100.1100_2=C.C_{16}$。这里只是把同一个值换一种写法，并没有改变它的数值。

![十二点七五分别转换整数与小数部分得到二进制](/images/posts/computer-systems/lab03/lab03-07-base-conversion.png)

#### 1.2.6 为什么有些小数不能转换完

前面把 0.75 转成二进制时，我们乘了两次 2，小数部分就变成了 0，所以转换也就结束了。但是，如果换成 0.1，还能这么顺利吗？

我们照样用“乘 2 取整”的方法试一下：

$$
\begin{aligned}
0.1\times2 &= 0.2 &&\text{取整数 0，剩下 0.2}\\
0.2\times2 &= 0.4 &&\text{取整数 0，剩下 0.4}\\
0.4\times2 &= 0.8 &&\text{取整数 0，剩下 0.8}\\
0.8\times2 &= 1.6 &&\text{取整数 1，剩下 0.6}\\
0.6\times2 &= 1.2 &&\text{取整数 1，剩下 0.2}
\end{aligned}
$$

你会发现，最后剩下的又是 0.2，而这个数我们在第一步就遇到过了。继续算下去，就会重复“0.2 → 0.4 → 0.8 → 0.6 → 0.2”这个过程，小数部分始终变不成 0，也就是说我们最后得到的其实就是$0.1_{10}=0.0001100110011\cdots_2$

也就是说，一个数在十进制里只需要一位小数，换成二进制后，却可能需要无限多位，这和十进制里 $1/3=0.333\cdots$ 有点类似

那怎么提前判断一个小数能不能转换完呢？我们可以先把它写成最简分数。如果能写成有限位二进制小数，那么保留 m 位小数后，它一定可以写成 $k/2^m$ 的形式。因此，约分后的分母只能含有因子 2，也就是必须是 2 的幂。即，当分母是 2 的幂时，我们就能用有限位二进制表示。

比方说，$0.75=3/4$，分母是 $2^2$，所以能转换完。而 $0.1=1/10$，分母里还有一个 5，怎么约也去不掉，所以会一直循环。

但计算机用来保存一个数的位数是有限的，不可能把后面的 `0011` 一直存下去。于是保存 0.1 时，只能在某个位置停下来，再按舍入规则选一个能存下的近似值。后面讲浮点数时，我们还会遇到这个问题：有时输入的是 0.1，机器里保存的却只是一个很接近 0.1 的数。

### 1.3 定点数与浮点数

先看同一串二进制 `101`，小数点放的位置不同，值也不同：

| 小数点放在哪 | 按二进制读作 | 十进制值 |
| --- | --- | --- |
| 最右边 | $101.0_2$ | 5 |
| 中间 | $10.1_2$ | 2.5 |
| 最左边 | $0.101_2$ | 0.625 |

**定点数：提前约好小数点在哪，所有数都按这个位置读。** 小数点本身不存进内存。上表第一种是定点整数，第三种是定点小数，中间一种也是定点表示的例子。

定点不等于只能表示整数。比方说，用 8 位补码保存整数 24，约定读取时统一除以 $2^4$，它就可以代表 $24/16=1.5$。这里的缩放比例是提前约好的，不需要另外存储。

**浮点数：像科学计数法，把有效数字和“放大、缩小多少”分开保存。** 比方说，$\underbrace{1.01_2}_{\text{尾数}}\times\underbrace{2^{2}}_{\text{阶为 2}}=101.0_2=5_{10}$，尾数不变，把阶改成 -1，就变成 $1.01_2\times2^{-1}=0.101_2=0.625_{10}$。阶决定小数点向哪边移动、移动几位，而这就是“浮点”的意思。

浮点表示把这个缩放比例也编码保存，一般写成 $N=(-1)^S M R^e$，其中 S 决定正负，M 保存有效数字，e 决定缩放的数量级，基数 R 通常由格式约定。同样的总位数下，多分一些位给阶码，可以扩大表示范围；多分一些位给尾数，可以提高精度。不过这里不用看太详细，具体的浮点格式放在第 3 节。

### 1.4 定点数的编码表示

带符号数需要把正负号也编码进去。下面先用 8 位整数举例，再补充定点小数的情况。

#### 1.4.1 原码

原码采用“符号位+数值部分”的形式：最高位为 0 表示正，为 1 表示负，其余位表示绝对值。

例如，+7 的 8 位原码是 `00000111`，-7 的 8 位原码是 `10000111`。

#### 1.4.2 反码

正数的反码与原码相同；负数则保留原码符号位，把数值部分逐位取反。

例如，-7 的原码是 `10000111`，反码就是 `11111000`。

#### 1.4.3 补码

正数的补码、反码和原码相同；负数的补码可以在反码的基础上加 1 得到。

例如，-7 的原码为 `10000111`，反码为 `11111000`，再加 1，得到补码 `11111001`。

![负七从原码经反码转换为补码](/images/posts/computer-systems/lab03/lab03-02-twos-complement.png)

补码的一个重要作用是把减法转换成加法，使计算机可以利用同一个加法器完成加减运算。这里先看编码，后面的补数法和 6.4 节会把它与运算联系起来。

对于 n 位补码整数，负数 x 的编码可写成 $[x]_补=2^n+x$；非负数的编码就是它本身。也可以统一写成 $[x]_补=x\bmod 2^n$

于是就有人要问了，主播主播，既然你这个补码一个就够用了，那你为什么还要这个反码呢，然后你这历史上原码、反码和补码又是怎么搞出来的，又是谁定义的，又有什么用呢

首先，我们先列出一个表格，看看同一个东西，我们跟外国人是怎么称呼的，从而打破我们的固化思维

| 中文教材 | 英文名称         | 实际含义      |
| -------- | ---------------- | ------------- |
| 原码     | sign-magnitude   | 符号+数值大小 |
| 反码     | one's complement | 一的补数      |
| 补码     | two's complement | 二的补数      |

补数，本质上是指，为了“补到一个整轮”，还差多少，后面我们会频繁提及它，因为它是将减法变为加法的关键

在机械计算器时代，人们就发现，如果机器只擅长做加法，那么有没有什么办法把减法也变成加法。答案就是“补数法”

举个十进制的例子，假设我要算$725-348$，如果计算机不方便直接减$348$，怎么办？此时我们固定使用三位十进制数，那么此时整个空间就是$000\sim999$。999后面就是1000，此时我们**注意到**$1000-348=652$，那么$725+652=1377$。因为我们固定只保留三位，千位的 1 不保存，剩下的 377 正好就是$725-348=377$。也就是说$-348$在计算机中，我们完全可以用$652$来代替。而这就是所谓的$10^n-x$，即所谓的“十的补数”。
这种“用补数把减法变成加法”的思想在机械计算器时代就已经被实际使用了，例如早期 Comptometer 一类机械计算器就是通过加入补数来完成减法，所以说，补码其实就是一个古老的算数技巧在二进制上的应用，而不是突然想出来的奇怪编码

那么反码又是怎么来的？继续看这个348，它对于十的补数是$1000-348=652$，但是早期机械设备有一个问题，直接算$1000-348$仍然涉及减法，不够方便，于是数学上可以将其变成$(999-348)+1$。为什么这样就方便了？因为对于括号内的算式，每一位我们都可以进行独立计算，比如$9-3=6$,$9-4=5$,$9-8=1$，所以$348 \rightarrow 651$，这叫九的补数(9's complement)。然后再加1后，就变成了十的补数(10's complement)

此时这个结构已经特别眼熟了，这也就是我们的“反码(1's complement)+1 $\rightarrow$ 补码(2's complement)”。那么为什么二进制里面我们叫他们一的补数和二的补数呢？这是由进制决定的，不是哪个超级计算机大牛拍脑袋规定的。
一般来说，如果使用b进制、固定n位，会自然出现两种补数，$b^n-1-x$（减基数补数）以及$b^n-x$（基数补数）。所以对于十进制，$10^n-1-x$称为9的补数，$10^n-x$是10的补数，同样的，$2^n-1-x$是1的补数，$2^n-x$是2的补数

为什么1的补数恰好就是按位取反呢？假设在4位的情况下求3的1's complement，那么按照定义就是$1111_2-0011_2=1100_2$，你会发现每一位都翻转了，因此在二进制里$(2^n-1)-x \Leftrightarrow \text{所有bit取反}$，这就是为什么1's complement 在中文里叫反码

那补码为什么又是反码+1？2‘s complement是$2^n-x$，这个等价于$(2^n-1-x)+1$，由于2's complement = 1's complement+1，所以补码=反码+1

在$1940\sim1960$年代，sign-magnitude,one's complement,two's complement其实都有人用，此时并不是全世界都知道补码最好，当时是不同的设计团队做出不同选择，例如：

- IBM 704、709 等机器采用过 sign-magnitude；
- PDP-1、CDC 6600、UNIVAC 1107 等采用过 one's complement；
- EDSAC、后来的一批 DEC 机器以及 IBM System/360 等采用 two's complement。


所以严格来说，补码并不是冯·诺依曼从零“发明”的。利用补数把减法转换成加法的思想，在机械计算器时代早已存在。冯·诺依曼的重要贡献之一，是在1945年的《First Draft of a Report on the EDVAC》中明确建议在二进制电子计算机中采用 two's complement 一类的表示和运算方式。随后，EDSAC、IBM System/360 等计算机采用 two's complement，这种方案也逐渐成为现代计算机表示有符号整数的主流。

教材还用钟表说明同一个道理：在一个 12 小时的表盘上，往回拨 3 小时，与往前拨 9 小时会到达同一个位置。这里的 12 就是模，-3 与 9 在模 12 下等价。固定 n 位二进制整数只有 $2^n$ 种编码，最高位以外的进位被丢弃，对应的模就是 $2^n$。

在补码运算中，有时还会把符号位扩展成两位，这叫**变形补码**，也叫模 4 补码。两位符号为 `00`、`11` 时，分别表示没有溢出的非负数和负数；结果变成 `01`，表示正溢出，变成 `10`，表示负溢出。它用额外的一位帮助判断运算是否越界，不是说 C 的 `int` 会额外存两个符号位。

#### 1.4.4 移码

移码 `Biased Representation` 的思想是给真值统一加上一个固定的偏置值 $E=e+Bias$，相当于把整条数轴向右平移

移码的一个重要特点是编码大小与真值大小顺序一致，因此特别适合表示浮点数的阶码

IEEE 754 使用的指数编码本质上就是一种偏置表示，只不过它的 Bias 对 `float` 为127，对 `double` 为1023，后面浮点数部分会详细讲

#### 1.4.5 编码、真值与零的对应关系

把几种编码放到一起看，区别会更清楚。下面都采用 8 位整数编码。

| 真值 | 原码 | 反码 | 补码 | 偏置为 128 的移码 |
| --- | --- | --- | --- | --- |
| +7 | `00000111` | `00000111` | `00000111` | `10000111` |
| -7 | `10000111` | `11111000` | `11111001` | `01111001` |
| +0 | `00000000` | `00000000` | `00000000` | `10000000` |
| -0 | `10000000` | `11111111` | 与 +0 相同 | 与 +0 相同 |

对于 n 位补码整数，把编码看成无符号数得到 U 后，可按下面的公式恢复真值：

$$
x=\begin{cases}
U,&0\le U<2^{n-1}\\
U-2^n,&2^{n-1}\le U<2^n
\end{cases}
$$

比方说 `11111001` 的无符号值为 249，补码真值就是 $249-256=-7$，这比先转换成原码再读数更直接。

求一个补码数的相反数，可以对全部位取反再加 1，但要留意最小负数：8 位的 `10000000` 这样操作后仍是 `10000000`，因为 +128 根本放不进 8 位补码。公式在模 $2^8$ 下成立，不代表相反数一定能用同样的带符号位宽表示。

#### 1.4.6 定点小数的范围

若总共 n 位，其中 1 位是符号位，则原码定点整数范围为 $-(2^{n-1}-1)\sim 2^{n-1}-1$，原码定点小数范围为 $-(1-2^{-(n-1)})\sim 1-2^{-(n-1)}$。原码和反码都有正零、负零两种编码。

补码只有一个零，多出来的编码用于表示最小负数，所以补码定点整数范围是 $-2^{n-1}\sim2^{n-1}-1$，补码定点小数范围是 $-1\sim1-2^{-(n-1)}$。补码最高位可以理解成负位权：整数时为 $-2^{n-1}$，小数时为 $-1$。

教材常见的 n 位移码偏置为 $2^{n-1}$，相当于把同位宽补码的最高位取反。IEEE 754 阶码的偏置则是 $2^{k-1}-1$，不要把这两个偏置混在一起。

## 2. 整数的表示

### 2.1 无符号整数和带符号整数

比方说，现在有 8 个 bit 的`11111111`，我们要算它的值，那么这就要看我们把它当成什么类型的数。

- **按无符号数读**：每一位都表示正的数值，加起来就是 $128+64+32+16+8+4+2+1=255$。
- **按补码读**：最高位的 1 表示的是 -128，其余位照常算，所以得到 $-128+64+32+16+8+4+2+1=-1$。（当然可能不少人看到这个算法会眼前一亮，然后说一句，我chory你算给我算好了呀。这个其实是补码的另一种等效的算法。~~终于知道为什么正派这么讨厌邪修了~~）

所以，同样是 `11111111`，按无符号数解释是 255，按补码解释就是 -1。bit 没变，变的是我们怎么算它的值。山一直在那，看的是我们怎么理解它（bushi）

如果最高位是 0，两种读法就没有这个区别了。比方说，`01111111` 无论按无符号数还是补码读，都是 127。

初步总结下，在 C 语言中，`int` 可以表示正数、负数和 0，`unsigned int` 只能表示非负整数。

那于是就有人要问了：你说他们可以表示这些数，那它们分别能表示多大的数呢？

对于 n 位机器数：

- 带符号补码的范围是 $-2^{n-1}\sim2^{n-1}-1$
- 无符号数的范围是 $0\sim2^n-1$

所以假设 `int` 和 `unsigned int` 都用 32 位表示，那么 `int` 的范围是 $-2^{31}\sim2^{31}-1$，`unsigned int` 的范围是 $0\sim2^{32}-1$。这里记个数字，$2^{31}=2147483648$。

前面的 `11111111`，两种读法的结果相差 $255-(-1)=256=2^8$。换成 32 位全是 1 的 `FFFFFFFFH`，按补码读是 -1，按无符号数读就是 $-1+2^{32}=4294967295$。

### 2.2 C 语言中的无符号整数

课本接下来会讲 C 语言中的整数转换。我这里先单独展开无符号整数：它为什么出现，有哪些类型，怎样参与运算，又为什么会影响后面的比较、循环和内存访问。先把这些弄清楚，再回到整数转换的例子，就容易理解得多。下面的程序采用 C11，运行环境仍是 x86-64 Linux/WSL。

#### 2.2.1 无符号类型的由来

C 语言和 Unix 的发展是连在一起的。早期 Unix 主要用汇编语言编写，能直接操作硬件，但写起来比较繁琐，换一种机器时也往往需要改动很多代码。开发者希望用一种比汇编更方便的语言来写系统程序，同时又能操作内存、处理字节，让程序有效地运行在当时资源有限的机器上。

在这个过程中，Ken Thompson 先发展出了 B 语言，Dennis Ritchie 又在 B 的基础上逐步发展出 C。到 1973 年，C 已经能够承担操作系统的开发，Unix 内核也在这一年的夏天用 C 重写。因此，C 从发展之初就需要面对“怎么访问内存、怎么组织数据、怎么与硬件打交道”这些具体问题。[Dennis Ritchie：The Development of the C Language](https://cm-bell-labs.github.io/who/dmr/chist.html)

写系统程序时，一方面要处理数值，比如计算数量、长度和差值；另一方面要通过指针访问内存中的数据。简单来说，一个是在算“是多少”，另一个是在找“存在哪”。

先看数值：差值可能为负，但数量、长度通常不需要负数。如果一种整数类型不表示负数，就能把原来用于负数的那部分编码，用来表示更大的非负整数。这是无符号整数的一个用途。

再看指针：内存里的每个字节都有地址，可以先把地址理解成字节的编号。程序通过指针找到对象，就涉及这些地址。而在早期 C 所面对的一些机器上，地址的大小顺序恰好更像无符号数，而不是带符号数。

现在想象一台用 16 位给内存字节编号的机器，编号从 `0000H` 一直到 `FFFFH`。其中两个紧挨着的编号是：

| 同一串 16 位编码 | 按内存地址编号看 | 按 16 位补码整数看 |
| --- | --- | --- |
| `7FFFH` | 32767 | 32767 |
| `8000H` | 32768 | -32768 |

按地址编号看，32768 就在 32767 后面。但我们如果把这串 bit 当成带符号整数，最高位一变成 1，读出来的值就成了 -32768，我们并不希望地址因此被当成负数。因此，在这个简单的地址模型里，地址编号的大小顺序更像无符号整数。另外，一个指向字节的指针前进一个字节，地址编号就增加 1，看起来又很像整数加法。

而早期 C 对指针和整数的区分还很松。早期《C Reference Manual》允许整数与指针直接赋值，直接保存那份值。这就使得“拿一个数做计算”和“拿一个地址找内存位置”容易混在一起。这里可以参考[早期 C 手册，7.14.1](https://cm-bell-labs.github.io/who/dmr/cman.pdf)

后来，C 加入了独立的无符号类型。如果我们需要一个不表示负数、按无符号规则计算的整数，就可以直接声明 `unsigned`，不必再把这类计算和指针操作混在一起。Ritchie 在回顾中明确提到了这个设计动机，并把 `unsigned` 列在 1973～1980 年间逐步加入的类型特性中。有兴趣可以查看[Dennis Ritchie：The Development of the C Language](https://cm-bell-labs.github.io/who/dmr/chist.html)

这里的地址编号例子是为了说明当时两者为什么容易混淆。现代 C 中，指针和无符号整数仍然是不同的类型，指针运算有自己的范围限制，不能照搬无符号整数的回绕规则。

#### 2.2.2 整数类型、字符编码与格式化输出

`char`、`short`、`int`、`long`、`long long` 都属于整数类型，都能保存整数。类型决定分配多少空间、能表示哪些数，以及怎样参与运算。名字有的强调用途，有的强调大小关系，但 `char` 并不是字符专用类型。

| 类型 | 本文环境中的大小 | 对应的无符号类型及范围 |
| --- | --- | --- |
| `char` | 1 字节 | `unsigned char`：0～255 |
| `short` | 2 字节 | `unsigned short`：0～65535 |
| `int` | 4 字节 | `unsigned int`：0～4294967295 |
| `long` | 8 字节 | `unsigned long`：$0\sim2^{64}-1$ |
| `long long` | 8 字节 | `unsigned long long`：$0\sim2^{64}-1$ |

单独写 `unsigned` 就是 `unsigned int`。它不增加对应类型的空间，而是改变数值范围和相应运算规则。具体大小仍要看平台，比如常见 64 位 Windows 的 `long` 仍是 4 字节。

先看同一个整数 65。下面三个变量保存相同的数值，但分别占 1、4、8 字节；打印形式则由格式符决定：

```c
char a = 65;
int b = 65;
long long c = 65;

printf("%d\n", a);   // 65：char 在这里会提升为 int
printf("%d\n", b);   // 65
printf("%lld\n", c); // 65

printf("%c\n", a);   // A
printf("%c\n", b);   // A：int 也可以按字符输出
```

理解这段代码，需要分清三个步骤：**变量保存值，`printf` 把值转换成输出字节，终端再把这些字节当成文字显示。**

先看变量。`char a = 65;` 保存的一个字节是 `01000001`，即十六进制 `41`。`int b = 65;` 则用 4 字节保存整数 65，在本文的小端环境中是 `41 00 00 00`。两者占的空间不同，数值相同。

再看字符编码。ASCII 是一张对应表，规定字符 `A` 对应整数 65，字符 `6` 对应 54，字符 `5` 对应 53。因此，在我们的环境中，写 `'A'` 就是在用字符写法表达编码值 65，`char a = 'A';` 与 `char a = 65;` 保存相同的值。

最后看打印。`printf` 不会直接把变量占用的所有字节倒给终端，它先读取参数的数值，再根据格式串生成输出：

| 调用 | `printf` 做什么 | 生成的输出字节（十六进制） | 屏幕显示 |
| --- | --- | --- | --- |
| `printf("%d", 65)` | 将整数写成十进制文字，得到字符 `6`、`5` | `36 35` | `65` |
| `printf("%c", 65)` | 把 65 转为单个字符字节 | `41` | `A` |

第一行的 `36` 是十进制 54，也就是字符 `6` 的编码；`35` 是十进制 53，也就是字符 `5` 的编码。终端收到两个字节，依次显示 `6` 和 `5`。第二行发出的是一个值为 65 的字节，终端按编码显示 `A`。所以“输出一个字节”说的是传出去的数据量，不是让屏幕显示这个字节的数值。

这些字节通常经过标准输出缓冲，再由操作系统送到终端；不意味着每个字节都单独触发一次系统调用。`\n` 也属于输出内容，在本文环境中占一个换行字节。

这也说明，**变量大小与输出长度没有固定对应关系**。一个 4 字节的 `int` 保存 123456789，`printf("%d", x)` 会生成九个数字字符，输出 9 字节；加上 `\n` 后是 10 字节。打印不会改变 x，也不会把 x 扩成 9 字节。

格式符仍要匹配参数类型：`%d` 接收 `int`，`%lld` 接收 `long long`，`%c` 接收 `int` 并转换成 `unsigned char` 后输出。本文环境中的 `char` 传给 `printf` 时先提升为 `int`，因此能直接用于上面的 `%d`、`%c`。`long long` 若要按 `%c` 输出，需要先明确转换成 `int`。

`char` 适合逐字节保存数据。`char text[] = "Hello";` 保存五个字母的编码与结尾的 0，共 6 字节，不必给每个字母都分配一个 `int`。但它也可以保存与字符无关的小整数，例如 `unsigned char brightness = 200;` 用 200 表示颜色强度。

| 字符整数类型 | 本文 8 位字节、补码环境中的范围 |
| --- | --- |
| `signed char` | -128～127 |
| `unsigned char` | 0～255 |
| 普通 `char` | 采用上述哪种范围，由编译器及设置决定 |

C 把这三者视为不同的类型。需要明确按 0～255 处理字节时，写 `unsigned char`。ASCII 只定义 0～127，所以 255 能保存，却没有对应的标准 ASCII 字符；UTF-8 中单独的 `FF` 也不是合法的字符编码。另一方面，“中”需要 UTF-8 字节 `E4 B8 AD`，一个字节又装不下一个完整汉字。因此，字节、数值、字符与屏幕上的字形不能混为一谈。

#### 2.2.3 无符号运算与整数提升

这里要区分“类型能表示什么”和“赋值时允许发生什么转换”。无符号类型不能表示负值，但 C 允许把整数转换成无符号类型，转换结果按照目标类型的范围取模。

对于有 n 个值位的目标类型，转换结果是与原整数模 $2^n$ 同余、且处于 $0\sim2^n-1$ 的那个值。

```c
unsigned char byte = -1;   // 8 位 unsigned char：255
unsigned int word = -1;    // 32 位 unsigned int：4294967295
```

所以，byte 并没有偷偷保存一个负数，而是在赋值时把 -1 转换成了 255。也不能把这种转换理解成取绝对值，-1 的绝对值是 1，和这里的结果没有关系。

无符号类型自身的加、减、乘运算，也遵循模运算规则。比方说，32 位 `unsigned int` 的 `UINT_MAX + 1U` 得到 0，而 `0U - 1U` 得到 `UINT_MAX`。可以想象一个只有 $2^{32}$ 个刻度的表盘，走过最大刻度后就回到 0。

不过，变量的类型不一定就是表达式实际计算时的类型。`char`、`short` 等较窄的整数参加运算时，会先发生整数提升：如果 `int` 能表示原类型的全部值，就提升为 `int`，否则提升为 `unsigned int`。所以，两个无符号变量相减，也可能先得到一个有符号结果：

```c
unsigned char a = 0;
unsigned char b = 1;

printf("%d\n", a - b);                  // -1
printf("%u\n", (unsigned int)(a - b));  // 4294967295
printf("%u\n", (unsigned int)(unsigned char)(a - b)); // 255
```

在我们的环境中，`int` 可以表示 `unsigned char` 的全部取值，所以 a 和 b 在相减之前都先提升为 `int`。实际计算的是 `int` 类型的 `0 - 1`，结果当然就是 -1。

第二行再把这个 -1 转换成 32 位 `unsigned int`，得到 4294967295；第三行先转成 8 位 `unsigned char`，得到 255，然后为了配合 `%u`，再转成 `unsigned int`。

同样，`unsigned char c = 255;` 之后，`c + 1` 在当前环境中得到的是 `int` 类型的 256；如果把结果赋回 c，才在转换回 `unsigned char` 时得到 0。

所以判断一段代码时，需要沿着“变量类型 → 整数提升 → 表达式结果类型 → 赋值转换”往下看。只看到变量名旁边有个 `unsigned`，还不能确定整个表达式怎样计算。

甚至两个 16 位 `unsigned short` 相乘，在 32 位 `int` 环境中也可能先提升为 `int`，然后因为乘积过大而发生有符号溢出。需要无符号乘法时，应在相乘之前转换操作数，而不是等相乘结束再转换结果。

这些类型规则最终由编译器落实到机器指令上。内存中的一个普通整数对象，并不会在旁边再保存一个“这是 unsigned”的标签。编译器根据源码中的类型规则，选择合适的机器指令；CPU 则按照指令的含义处理位串。

在 x86 中，同一宽度的普通加法可以使用同一种 `add` 指令。比方说，在 8 位加法中，`FFH + 01H` 保留低 8 位得到 `00H`：按无符号数解释，是 255+1 后产生进位；按补码解释，是 -1+1，结果为 0。硬件对这次加法可以同时更新进位标志 CF 和溢出标志 OF，后续代码根据需要检查不同的标志。

不过，比较后的条件跳转就要区分含义。x86 的 `cmp` 可以相同，但有符号“小于”通常使用 `jl`，无符号“低于”通常使用 `jb`；右移也有算术右移 `sar` 和逻辑右移 `shr` 的区别。本文采用的 GCC 在负有符号数右移时采用符号扩展，而无符号右移补 0。[GCC：整数实现说明](https://gcc.gnu.org/onlinedocs/gcc/Integers-implementation.html)

所以两个变量占用相同的位数，不代表它们在所有运算中都可以互换。也不能据此认定 `unsigned` 总是更快：有些操作可以使用相同指令，有些操作会生成不同指令，实际还受表达式和优化影响。选类型时先确定数值范围与需要的运算规则，不必为了一个没有测量过的速度优势把 `int` 全部改成 `unsigned int`。

还有一个界限不能混过去：即使 CPU 的 `add` 会保留低位，C11 的有符号加法溢出仍然属于未定义行为。不能只凭一次机器指令的输出，就把硬件现象当成 C 源码在所有优化条件下的保证。

#### 2.2.4 对象的字节表示

前面用 `unsigned char` 保存一个字节的数值，现在再用它看看一个整数究竟由哪些字节组成。比方说，`unsigned int x = 0x12345678U;` 在本文环境中占 4 字节，我们想把这 4 个字节分别读出来，而不是一次读出整个整数。


![同一块四字节内存按整数和按字节访问的区别](/images/posts/computer-systems/lab03/lab03-byte-pointer-access-v1.png)

这里的 `78`、`56` 等都是十六进制写法。小端就是把一个数的低位字节放在低地址；第 5 节会继续讨论存储顺序。这里先看怎样把这四个字节逐个读出来。

`&x` 表示取 x 的地址，类型是 `unsigned int *`。如果用这种指针加 1，就会直接前进一个 `unsigned int` 的大小，也就是 4 字节。我们想每次只前进 1 字节，所以把地址转换成 `unsigned char *`：

```c
unsigned int x = 0x12345678U;
const unsigned char *p = (const unsigned char *)&x;
```

p 仍然指向 x 开头的那个位置，但现在通过 p 访问时，每次读取一个字节：

| 访问方式 | 读取的位置 | 读到的字节值（十六进制） |
| --- | --- | --- |
| `p[0]` | x 的第 1 个字节 | `78` |
| `p[1]` | x 的第 2 个字节 | `56` |
| `p[2]` | x 的第 3 个字节 | `34` |
| `p[3]` | x 的第 4 个字节 | `12` |

**转换的是指针类型，x 本身没有变。** 我们只是从“把四个字节一起读成一个整数”，换成了“每次只读其中一个字节”。C 允许用字符类型的指针这样查看对象的内存表示，所以这里使用 `unsigned char *`。

这里再加上 `unsigned`，是为了把每个字节都按 0～255 读取。比方说，读到 `FF` 时，我们要看到的是 255，而不是把它解释成 -1。

把它写成循环，就能打印出这四个字节：

```c
#include <stdio.h>

int main(void){
    unsigned int x = 0x12345678U;
    const unsigned char *p = (const unsigned char *)&x;

    for(size_t i = 0; i < sizeof x; i++)
        printf("%02X ", (unsigned int)p[i]);
    putchar('\n');
    return 0;
}
```

这里的 `const` 表示不通过 p 修改这些字节。小端环境下，这段代码会依次打印 `78 56 34 12`。

**本文环境中的一个字节是 8 个二进制位，一个十六进制数码可以表示 4 个二进制位，所以一个字节正好可以用两位十六进制数表示。** 比方说，`0111 1000` 分成两组，每组四位，分别对应十六进制的 7 和 8，合起来就是 `78`。因此，我们用 `%02X`，让每个字节都显示成两位，不足两位时在前面补 0。

`%02X` 中，`X` 表示按十六进制输出，字母用大写；`2` 表示至少显示两位；`0` 表示不足两位时，在前面补 0。比方说，同一个字节值 `0x0A`，用不同格式输出：

| 格式 | 输出 |
| --- | --- |
| `%01X` | `A` |
| `%02X` | `0A` |
| `%03X` | `00A` |

**这里的 2 控制的是打印宽度，不是字节的位数。** 它规定的是最小宽度，超过两位的数也不会被截掉。

如果还想查看其他变量，就把这段循环提取成函数：

```c
void show_bytes(const void *object, size_t size){
    const unsigned char *p = object;

    for(size_t i = 0; i < size; i++)
        printf("%02X ", (unsigned int)p[i]);
    putchar('\n');
}
```

`object` 接收要查看的对象地址，`size` 接收要查看的字节数。`const void *` 让这个参数可以接收不同对象类型的地址，函数内部再转成 `const unsigned char *`，统一逐字节读取。

比方说，写 `show_bytes(&x, sizeof x);`，就是“从 x 的地址开始，查看 x 占用的全部字节”。换成 `int y = -32768;`，再调用 `show_bytes(&y, sizeof y);`，在本文环境中就会看到 `00 80 FF FF`，和 GDB 中用 `x/4xb &y` 查看这同一个变量时读到的内存字节一致。

注意，`(unsigned char)x` 是把 x 的数值转换成一个字节范围内的整数；`(const unsigned char *)&x` 则是让指针从 x 的地址开始逐字节查看。前者在转换数值，后者在改变访问方式，不是一回事。

#### 2.2.5 无符号整数的应用

`sizeof` 的结果类型是 `size_t`，它是实现定义的无符号整数类型，不是固定写死的 `unsigned int`。在我们的 x86-64 Linux 中，它通常对应 `unsigned long`。

数组长度、对象大小经常使用 `size_t`，比方说：

```c
int a[] = {10, 20, 30};
size_t count = sizeof a / sizeof a[0];

for(size_t i = 0; i < count; i++)
    printf("%d\n", a[i]);
```

这里的 `sizeof a / sizeof a[0]` 适用于 a 仍然是数组的地方；函数参数中的 `int a[]` 会调整为指针，不能照搬这个式子来获取调用者数组的长度。

但是“长度不可能为负”不代表所有和长度有关的计算都适合直接用无符号减法。比方说，两个长度相减，如果我们想保留“短了多少”这个负结果，就不能直接假设 `size_t` 会表示它。指向同一数组中元素的两个指针相减，结果类型则是有符号的 `ptrdiff_t`，而且差值还必须能由该类型表示。

顺序循环可以直接比较下标和长度；倒序时，也应避免在长度为 0 时先计算 `count-1`：

```c
/* 不要这样写：i 是无符号数，i >= 0 永远成立。 */
/* for(size_t i = count - 1; i >= 0; i--) ... */

for(size_t i = count; i > 0; ){
    --i;
    printf("%d\n", a[i]);
}
```

这种写法也能处理 `count=0`，不会在进入循环前先算出 `count-1`。

除了保存长度，无符号整数也经常用来保存一组开关状态，每一位分别表示某个功能是否开启。比方说，用第 0 位表示可读、第 1 位表示可写：

```c
unsigned int flags = 0U;
const unsigned int READ = 1U << 0;
const unsigned int WRITE = 1U << 1;

flags |= READ;                  // 打开可读位
flags |= WRITE;                 // 打开可写位
int can_write = (flags & WRITE) != 0U;
flags &= ~WRITE;                // 关闭可写位，保留其他位
```

这里的 `U` 是整数字面量后缀，让 `1U` 具有无符号类型。对于当前 32 位 `unsigned int`，`1U << 31` 可以构造最高位为 1 的位掩码，而 C11 中 `1 << 31` 会因为有符号结果无法表示而产生未定义行为。

但是 `U` 也不是让所有移位都合法的护身符。移位次数仍然必须非负，而且小于左操作数提升后的位宽；32 位 `unsigned int` 的 `1U << 32` 就不合法。无符号右移补 0，因此也便于从高位中提取字段。

如果要处理一个 32 位文件字段，可以在实现提供 `uint32_t` 时使用它；但 `1U` 的类型仍然是 `unsigned int`，并不会因为赋给了 64 位变量就提前变成 64 位。比方说，当前环境中构造第 40 位，可以使用 `1ULL << 40`。

设备寄存器也经常用无符号位字段表示状态，但真正访问硬件还要遵循设备手册、操作系统接口和相应的访问规则，普通 `unsigned int` 变量本身不会自动变成设备寄存器。

处理文件和网络报文时，还需要明确字段的宽度。假设一个文件格式规定“接下来的字段恰好是 4 个八位字节”，那它要求的是确定的位数，而 `unsigned int` 的名字本身并没有跨平台保证 32 位。

C99 加入的 `<stdint.h>` 提供了 `uint8_t`、`uint16_t`、`uint32_t`、`uint64_t` 等固定宽度类型。它们在实现能够提供相应精确宽度类型时才会定义。我们的 WSL 环境提供这些类型，表示协议字段或指定宽度的机器数时就很方便。

不过，固定宽度只规定了数值表示的宽度，**并没有替我们规定大小端**。比方说，从一个按高字节在前保存的报文中读取两个八位字节，可以写：

```c
unsigned char packet[2] = {0x12, 0x34};
unsigned int value = ((unsigned int)packet[0] << 8) | packet[1];
```

这个例子在本文环境中得到 `0x1234`。我们根据协议明确组合两个字节，而不是直接把 `packet` 转成 `unsigned short *` 读取。后者既依赖主机的字节序，还可能碰到对齐和类型访问问题。

这些类型在输入输出时也需要区分。`printf` 根据格式串读取参数，不会去查询变量原本的声明，所以格式符要与参数配合。

| 类型或用途 | 十进制输出的常用写法 | 说明 |
| --- | --- | --- |
| `unsigned int` | `%u` | 八进制用 `%o`，十六进制用 `%x` 或 `%X` |
| `unsigned long` | `%lu` | 十六进制可以用 `%lx` |
| `unsigned long long` | `%llu` | 十六进制可以用 `%llx` |
| `size_t` | `%zu` | 不要假定它就是 `unsigned int` |
| `unsigned char` | `%hhu`，或转成 `unsigned int` 后用 `%u` | 传给可变参数函数时仍有整数提升 |
| `uint32_t` | `printf("%" PRIu32, value)` | 需要 `<inttypes.h>`，避免猜测其底层类型 |

扫描输入时规则也不同。比方说，`scanf("%hhu", &byte)` 需要 `unsigned char *`，不能写成 `scanf("%u", &byte)`，否则函数会按 `unsigned int *` 写入，可能破坏相邻内存。

另外，`%u` 输入转换可以接受带负号的文本，所以也不能靠“我用了无符号格式”就认为已经禁止用户输入负数。需要限制输入时，应检查文本、转换是否成功，以及数值是否处于业务允许的范围。

读取文件字符还有一个很容易踩的坑：`getchar()` 返回 `int`，因为它需要同时表示每个字节对应的 `unsigned char` 值和结束标记 `EOF`。因此应该先用 `int` 接收并判断 `EOF`，不能直接存进 `unsigned char` 再判断结束。

对于一个已经保存在普通 `char` 变量 c 中的字节，调用 `isalpha`、`isspace` 等 `<ctype.h>` 函数时，常写成 `isalpha((unsigned char)c)`，避免把负的 `char` 值作为普通字符传入。但 `EOF` 应在转换前单独判断，不能先转成 `unsigned char` 而丢失结束标记。

前面的内容可以用一个小程序串起来。它会同时显示各类型的宽度、8 位与 32 位转换的区别、整数提升、位掩码，以及 -32768 的实际内存字节。为了让 `%u`、`%X` 的参数类型明确，打印字节前都显式转换成 `unsigned int`。

```c
#include <stdio.h>
#include <limits.h>
#include <stdint.h>

static void show_bytes(const void *object, size_t size){
    const unsigned char *p = object;
    for(size_t i = 0; i < size; i++)
        printf("%02X ", (unsigned int)p[i]);
    putchar('\n');
}

int main(void){
    _Static_assert(CHAR_BIT == 8 && UCHAR_MAX == 255,
                   "This example needs 8-bit unsigned char.");
    _Static_assert(UINT_MAX == 4294967295U,
                   "This example needs 32-bit unsigned int.");

    unsigned char byte = UCHAR_MAX;
    unsigned char zero = 0, one = 1;
    unsigned int word = UINT_MAX;
    unsigned int flags = 0U;
    const unsigned int READ = 1U << 0;
    const unsigned int WRITE = 1U << 1;
    unsigned char packet[2] = {0x12, 0x34};
    int x = -32768;

    printf("CHAR_BIT = %d\n", CHAR_BIT);
    printf("bytes: uchar=%zu ushort=%zu uint=%zu ulong=%zu ullong=%zu\n",
           sizeof(unsigned char), sizeof(unsigned short),
           sizeof(unsigned int), sizeof(unsigned long),
           sizeof(unsigned long long));
    printf("unsigned char: 0..%u; unsigned int: 0..%u\n",
           (unsigned int)UCHAR_MAX, UINT_MAX);
    printf("(unsigned char)-1 = %u\n", (unsigned int)(unsigned char)-1);
    printf("(unsigned int)-1  = %u\n", (unsigned int)-1);
    printf("uchar 0 - 1      = %d (promoted to int)\n", zero - one);
    printf("uchar 255 + 1    = %d (before assignment)\n", byte + 1);
    byte = byte + 1;
    printf("stored in uchar  = %u\n", (unsigned int)byte);
    printf("UINT_MAX + 1U    = %u\n", word + 1U);
    printf("0U - 1U         = %u\n", 0U - 1U);

    flags |= READ | WRITE;
    printf("READ | WRITE     = 0x%X\n", flags);
    flags &= ~WRITE;
    printf("after clear WRITE= 0x%X\n", flags);
    printf("1U << 31        = 0x%08X\n", 1U << 31);
    printf("packet value    = 0x%04X\n",
           ((unsigned int)packet[0] << 8) | packet[1]);
    printf("sizeof(size_t)  = %zu; sizeof(int) = %zu\n",
           sizeof(size_t), sizeof(int));
    printf("x = %d; bytes   = ", x);
    show_bytes(&x, sizeof x);
    return 0;
}
```

这里最容易看出区别的就是连续三行：`uchar 255 + 1` 得到 256，赋回字节后才变成 0，而 `UINT_MAX + 1U` 直接得到 0。前者先在 `int` 中运算，再转换回 8 位类型；后者的运算类型本身就是 32 位 `unsigned int`。

最后的 `00 80 FF FF` 则说明，x 虽然是带符号的 `int`，但我们仍然能用 `unsigned char *` 观察它的各个字节。查看字节，并没有把 x 本身改成无符号整数。

但是，如果一个量本来就需要表示负数，比方说温度、带方向的偏移、差值，就不能为了“范围更大”随手改成 `unsigned`。表示对象大小时优先遵循接口使用 `size_t`，表示协议字段时检查位宽与字节序，表示普通可正可负的整数时则使用合适的有符号类型。

还要记住，编译器不会因为一个变量无符号就自动禁止业务上的错误。`unsigned int age = -1;` 在语言规则上可以完成转换，但这个年龄显然不符合我们的意思。无符号类型规定的是数值表示与运算规则，合理的输入范围仍然要由程序检查。

#### 2.2.6 无符号整数的使用问题

老师提到无符号数会给后面埋下一些“大雷”，问题就出在这里：**我们按普通整数理解代码，C 却会先做类型转换，再按实际的运算类型计算。** 比较、循环和内存大小检查都可能因此失效，而且程序不一定马上报错。

先看有符号下标和无符号长度的比较：

```c
int index = -1;
unsigned int count = 10;

if(index < count){
    /* 我们可能以为 -1 < 10，所以一定进入。 */
}
```

在当前 32 位 `int` 环境中，比较前 index 会转换成 `unsigned int`，-1 变成 4294967295，条件反而为假。这会让一些判断失效，但也不能因此认为负下标被自动挡住了：如果程序只检查 `index > count`，或者换一种条件组合，错误就可能换个方向出现。

数组下标若用有符号类型接收，边界检查应该明确包含下界与上界。比方说，count 是 `size_t` 时，可以这样写：

```c
if(index >= 0 && (size_t)index < count){
    /* 在这里使用 index；count 应与实际数组长度相符。 */
}
```

在本文环境中，非负 int 可以由 `size_t` 表示。`&&` 从左到右求值，左边不成立就不计算右边，因此先排除负数，再转换检查上界。

还有一个更隐蔽的地方：**不必在这一行写出 unsigned，表达式也可能已经带着无符号类型。** 比方说 `sizeof` 的结果是 `size_t`，所以当前环境中的 `-1 < sizeof(int)` 也是假；`sizeof(int)` 看起来只是一个小小的 4，却改变了比较前的类型转换。

无符号长度的减法也会带来类似的问题。两个长度都没有负数，不代表它们的差也一定非负：

```c
/* 两个参数都是 size_t。这个比较不能判断 a 是否小于 b。 */
int shorter(size_t a, size_t b){
    return a - b < 0;
}
```

在本文的 x86-64 环境中，a-b 按 `size_t` 的无符号类型计算，结果不可能小于零。比方说，3-5 得到的是 `SIZE_MAX-1`，而不是 -2。

如果本来只是要比较大小，直接写 `a < b` 就好了，没有必要先减。类似的错误还会出现在字符串长度的比较中：`strlen(s) - strlen(t)` 是无符号减法，把回绕后的结果再塞进 `int`，也不是一个通用的修复方法。

而 `if(count - 1 >= 0)` 也不能用来检查 count 是否至少为 1。在当前环境中，即使 count 是 0，减一后还是一个很大的无符号值，条件仍然成立。正确的检查是 `count > 0`。

把“无符号数总是非负”带进循环条件，还可能让循环无法结束：

```c
/* 错误写法，不要实际运行这个循环。 */
/*
for(unsigned int i = 3; i >= 0; --i)
    printf("%u\n", i);
*/
```

我们想要的是 3、2、1、0，然后结束。但 i 从 0 再减一，会变成 `UINT_MAX`，`i >= 0` 仍然为真。循环会继续，而且如果 i 用来访问数组，在循环重复之前就已经可能越界。

窄类型还会带来另一种循环错误。比方说，8 位 `unsigned char i` 从 0 开始，使用 `i < 256` 作为条件：比较时 i 提升成 `int`，确实每次都小于 256；递增后存回 8 位对象，又从 255 回到 0，因此到不了退出条件。

需要递减访问数组时，前面的 `for(size_t i = count; i > 0; )`、循环内先 `--i` 的写法，可以同时处理空数组长度，避免依赖一个无符号的 -1 作为结束状态。

循环条件失效可能导致越界，容量检查里的回绕则可能直接放过一个过大的写入请求。

假设 capacity 是缓冲区容量，used 是已经使用的长度，extra 是准备追加的长度。我们很自然会写：

```c
/* 三者都是 size_t；这不是可靠的容量检查。 */
if(used + extra <= capacity){
    /* 以为放得下，然后追加数据。 */
}
```

但是 used+extra 可能先回绕，变成一个很小的数，再通过检查。对于本文环境，令 `used=16`、`extra=SIZE_MAX-7`，两者相加得到 8；如果 capacity 是 32，条件居然为真。

可以在加法之前，根据剩余容量检查：

```c
if(used <= capacity && extra <= capacity - used){
    /* 大小检查通过，再依据真实缓冲区与数据来源执行追加。 */
}
```

这里左边先保证 used 没有超过 capacity，右边的减法才不会下溢。不能省略前半句，否则所谓的“改用减法”也可能再次回绕。

申请内存的 `count * sizeof(element)` 是同一类问题：数学上的需求很大，机器得到的申请大小却很小；如果后续仍然写入 count 个元素，就会越过实际分配的空间。因此，应在乘法之前用 `count > SIZE_MAX / sizeof(element)` 检查，不能等乘完以后再判断。

**无符号回绕是定义好的算术行为，回绕后引起的越界访问仍然是未定义行为。** “标准规定会回绕”和“程序这样写是安全的”是两回事。

对于计数器，回绕可能是预期行为；对于内存分配，回绕成一个很小的大小就可能分配不足。

比方说，申请 count 个元素前，可以先检查乘法是否会超出 `size_t` 范围：

```c
#include <stdint.h>
#include <stdlib.h>

int *allocate_ints(size_t count){
    if(count == 0 || count > SIZE_MAX / sizeof(int))
        return NULL;

    return malloc(count * sizeof(int));
}
```

这个函数把零个元素也约定为返回空指针；即使大小计算没有溢出，`malloc` 仍可能失败，调用者需要检查返回值，用完后 `free`。这里先检查、再相乘，不能让乘法先回绕后再问结果是否超出了范围。

需要拒绝无符号加法回绕时，也可以在计算前检查 `b > UINT_MAX - a`；需要保留 a-b 的普通非负结果时，则先检查 `a >= b`。

无符号数的模运算可以用于某些校验和、散列和循环计数，不过具体算法仍然决定是否需要进位回卷或额外取模，不能把所有校验算法都等同于“丢掉高位”。而除零、越界访问、非法移位，也不会因为操作数无符号就变成合法行为。

扩大接收结果的变量，也不一定能解决范围问题，因为右边的运算可能已经在较窄的类型中完成：

```c
#include <stdint.h>

unsigned int a = 70000U;
unsigned int b = 70000U;
uint64_t wrong = a * b;
uint64_t right = (uint64_t)a * b;
```

在当前环境中，a*b 先按 32 位 `unsigned int` 计算。数学结果 4900000000 超出范围，回绕后是 605032704，然后才转成 `uint64_t` 保存。wrong 虽然有 64 位，也只是完整地保存了那个已经算错的值。

right 则是在乘法前就把一个操作数转成 `uint64_t`，让乘法在能容纳这两个 32 位无符号数乘积的类型中计算，因此得到 4900000000。

把 wrong 改写成 `(uint64_t)(a * b)` 仍然没用，因为括号里的 32 位乘法已经完成。这个问题在计算字节数、图像像素总量时很容易遇到：要看的不是等号左边有多大，而是等号右边实际用什么类型算。

反过来，两个较窄的无符号数也可能先提升成 `int`，使问题变成有符号溢出：

```c
unsigned short a = 50000;
unsigned short b = 50000;

/* 当前环境中有未定义行为，不能靠运行结果推导正确答案。 */
/* unsigned int wrong = a * b; */

unsigned int right = (unsigned int)a * b;
```

这就是前面整数提升埋下的另一层问题。在我们的环境中，`unsigned short` 是 16 位，`int` 是 32 位，因此两边先提升为 `int`，相乘得到的数学值是 2500000000，超过 `INT_MAX`。发生的是**有符号乘法溢出**，并不是无符号回绕。

即使最后准备用 `unsigned int` 接收，也改变不了乘法已经发生在 `int` 中。right 在运算前转换，才让这次乘法按 `unsigned int` 计算；2500000000 也恰好能由当前 32 位 `unsigned int` 表示。

注意，它并没有解决所有乘法的范围问题。如果乘积连 `unsigned int` 也装不下，仍然需要更宽的类型或在计算前检查。我们修复的是这个具体表达式的运算类型，不能把一次强制转换当成万能答案。

这些例子里，转换发生在计算前还是计算后，影响很大。但遇到混合比较的警告，也不能随手加一个强制转换，只为了让编译器安静下来。比方说，把 `index < count` 改成 `(unsigned int)index < count`。

这只是在源码中明确要求转换，负数照样会变成一个很大的无符号数，并没有检查 index 合不合法。如果错误地转换另一边，把一个很大的 count 转成 `int`，又可能丢失原本的取值范围。

所以转换之前要先回答：这个值有没有负数的可能？目标类型能不能表示它？我们到底是需要一个普通数值，还是有意使用模运算？这些问题没回答，警告消失也不能说明错误已经修好。

处理错误返回值时尤其要小心。比方说，POSIX 的 `read` 返回有符号的 `ssize_t`，用 -1 表示失败；如果直接存进 `size_t`，失败就会变成一个巨大的长度。应该先用 `ssize_t` 接收并检查是否小于 0，确认成功后再根据后续接口需要转换。

很多错误代码仍然能通过编译，是因为其中的转换和回绕本来就允许用于正常计算。

它们在处理位串、计数器时确实有用。编译器通常无法仅凭一个加法就知道，程序员想要的是表盘式回绕，还是一个绝对不能减少的内存大小。

可以额外开启这些警告，帮助我们发现可疑的混合比较、转换和条件：

```bash
gcc -std=c11 -Wall -Wextra -Wconversion -Wsign-conversion -Wtype-limits -g demo.c -o demo
```

`-Wsign-compare` 会检查一些有符号与无符号比较的问题，`-Wsign-conversion` 检查可能改变符号含义的隐式转换，`-Wtype-limits` 则能提示一些由类型范围决定、恒真或恒假的比较。显式强制转换可能消除部分警告，因此警告不能代替取值范围检查。

运行时也可以用 `-fsanitize=undefined` 辅助发现有符号溢出等未定义行为，但 GCC 的这个选项不会因为普通无符号回绕就报错，因为回绕本身有定义。程序没有收到诊断，并不等于大小计算符合我们的要求。

下面把几种情况放进同一个程序，对照错误条件与修正后的结果。程序只计算条件和表达式，不执行越界访问、无限循环或有符号溢出，因此可以直接观察错误形成的过程。

保存为 `unsigned_traps.c`：

```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>
#include <limits.h>

int main(void){
    _Static_assert(UINT_MAX == 4294967295U && USHRT_MAX == 65535U,
                   "This example needs 32-bit uint and 16-bit ushort.");
    int negative = -1;
    unsigned int ten = 10U, zero = 0U;
    size_t shorter = 3, longer = 5;
    size_t used = 16, extra = SIZE_MAX - 7, capacity = 32;
    unsigned int a = 70000U, b = 70000U;
    unsigned short small_a = 50000, small_b = 50000;

    printf("-1 < 10U             : %d\n", negative < ten);
    printf("-1 < sizeof(int)     : %d\n", negative < sizeof(int));
    printf("size_t 3 - 5         : %zu\n", shorter - longer);
    printf("unsigned 0 - 1       : %u\n", zero - 1U);
    printf("used + extra         : %zu\n", used + extra);
    printf("bad capacity check   : %d\n", used + extra <= capacity);
    printf("safe capacity check  : %d\n",
           used <= capacity && extra <= capacity - used);
    printf("widen after multiply : %" PRIu64 "\n", (uint64_t)(a * b));
    printf("widen before multiply: %" PRIu64 "\n", (uint64_t)a * b);
    printf("ushort safe multiply : %u\n", (unsigned int)small_a * small_b);
    puts("No out-of-bounds access, infinite loop or signed overflow is executed.");
    return 0;
}
```

### 2.3 C 语言中的整数及其相互转换

有了前面对无符号数的了解，我们再把它放回 C 语言的整数类型中，看不同类型一起运算时怎样提升、转换，以及这些规则为什么会影响比较和循环。

#### 2.3.1 整数类型、整数提升和输出格式

前面已经看过，变量声明的类型不一定就是表达式计算时的类型。正式讨论转换之前，把判断顺序再接起来：`char`、`short` 及其无符号类型先做整数提升；两个操作数若仍然不是同一类型，还要按照通常算术转换确定共同类型。比方说，在本文环境中，两个 `unsigned short` 相加时先提升成 `int`，并不是在 16 位中直接相加。

打印时也要让格式符和参数类型对应：`%d` 对应 `int`，`%u` 对应 `unsigned int`，`%ld` 对应 `long`，`%zu` 对应 `size_t`。想看 `-1` 转成无符号后的值，可以写 `printf("%u\n", (unsigned)-1);`，先明确转换，再打印，不能把更换格式符当成通用类型转换方法。

#### 2.3.2 有符号数与无符号数之间的转换

[**注**]：下面对同位宽整数转换的解释采用本课常见的补码实现。C90～C17 中，无符号数转成带符号数而超出范围时，结果由实现定义（或产生实现定义的信号）；不能把位模式解释直接当成所有实现的通用保证。

**当两个整数类型字长相同时**，在常见的补码机器上，有符号整数与无符号整数之间转换时，可以理解为底层二进制位保持不变，只是解释这些位的规则发生了改变

比方说，32位机器下，-1（int）的补码机器数为$FFFFFFFF_H$，将它解释为`unsigned int`，机器数仍然是$FFFFFFFF_H$，但是真值变成了4294967295，即$-1 \rightarrow 4294967295$

有同学注意到了，我特地给这个字长相同加重了，所以接下来我们要看这个不同字长整数之前的转换，不过也好理解：

**小字长 → 大字长**

- 无符号数：高位补0，称为**零扩展（Zero Extension）**
- 有符号补码数：高位复制符号位，称为**符号扩展（Sign Extension）**

**大字长 → 小字长**

- 在本文 GCC/补码环境中，可以用“截掉高位、只保留低位”观察转换结果，但真值可能改变。转成无符号类型时，标准规定按目标范围取模；超范围转成有符号类型时，仍要留意上面的实现说明。

![负一转换为无符号整数后位模式不变但真值改变](/images/posts/computer-systems/lab03/lab03-08-signed-unsigned.png)

#### 2.3.3 混合运算与整数常量的类型

这一块最重要的不是去背 `-1 < 0U` 到底是 `true` 还是 `false`，而是先搞明白，这些结果到底是怎么算出来的

在C语言中，整数参加运算时，不只是拿两个数学上的数直接算，因为每一个操作数本身都有类型，所以正式运算之前，C会先按照类型转换规则把两边转换成适合运算的共同类型，然后才真正进行比较、加减等操作

所以在此之前，我们还是需要把这个基础的规则搞明白

有人问，signed和unsigned到底是怎么对应的？

假设现在讨论32位整数，那么`unsigned int`的取值范围为$0\sim2^{32}-1$，也就是$0\sim 4294967295$，而32位有符号补码`int`的范围为$-2^{31}\sim2^{31}-1$，即$-2147483648\sim2147483647$

当一个负的有符号整数转换成32位无符号整数时，可以理解为对$2^{32}$取模，当然，对于负数`x`，取模的值无非就是加上$2^{32}$，即变成$x+2^{32}$

所以`-1`转换成`unsigned int`后得到$-1+2^{32} = 4294967295$，`-2` 转换后得到 $$-2+2^{32}=4294967294$$，而 `-2147483648` 转换后得到 $$-2147483648+2^{32}=2147483648$$

说白了，其实机器里的32个bit根本就没有变化，变化的只是我们怎么解释它们。比方说这个`-1`，32位补码是`FFFFFFFFH`，按照`int`解释就是`-1`，如果按照`unsigned int`解释就是`4294967295`

而有了这个基础，看下面的混合比较就完全是插标卖首了（bushi）

对于最常见的32位`int`和`unsigned int`，两者一起参与运算时，`int`会被转换成`unsigned int`，然后再进行运算

1. `-1 < 0U`

   `0U` 中的 `U` 表示这是一个 `unsigned int`，所以左边的 `-1` 也要转换成 `unsigned int`
   `-1`转换之后就是`4294967295U`，于是这个表达式实际上相当于`4294967295U < 0U`，显而易见，结果为`false`

2. `2147483647U > -2147483647 - 1`

   右边先按照普通 `int` 运算得到 `-2147483648`
   但是左边的 `2147483647U` 是 `unsigned int`，所以右边也要转换成无符号整数，而 `-2147483648` 转换以后得到 $-2147483648+2^{32}=2147483648$
   于是这个表达式最终比较的是 `2147483647U > 2147483648U`，所以结果为 `false`

3. `(unsigned)-1 > -2`

   `(unsigned)-1` 得到 `4294967295U`
   因为左边已经是无符号整数，所以右边的 `-2` 也转换成无符号整数，得到 `4294967294U`
   于是比较的是 `4294967295U > 4294967294U`，所以结果为 `true`

因此这类题真正的统一做法就是“先看两边的类型 → 确定是否发生转换 → 算出转换后的值 → 最后再比较”

但是，我们不能死记“有 unsigned 就全部转 unsigned”，上面讲的是最常见的 `int` 和 `unsigned int`。C语言完整的规则叫做 usual arithmetic conversions（通常算术转换），也就是说，实际还会考虑两边整数类型的等级和表示范围

例如在常见环境中，`long long` 是64位，而 `unsigned int` 是32位，此时64位 `long long` 完全能够表示32位 `unsigned int` 的全部取值，所以 `long long` 和 `unsigned int` 一起运算时，反而可以把 `unsigned int` 转换成 `long long`

而还有一点，就是代码里直接写出来的数字，本身也是有类型的，比如说0通常就是`int`了，`0U`是`unsigned int`，而`-1 < 0`和`-1 < 0U`是两种不同的比较，也就是说，仅仅多了一个U，整个表达式的运算方式就可能发生变化，类似的后缀还有L、LL


C90和C99对于整数常量类型的选择还有一个值得单独拿出来看的区别

这一块，最经典的例子就是`-2147483648 < 2147483647`

当然，在此之前，我们要先了解一点，c并不会把`-2147483648`看成一个完整的负整数字面量，而是先处理`2147483648`，然后再对它使用一元符号`-`

所以现在问题就落在这个`2147483648`了，也就是说，它到底是什么类型呢？

假设处在一种32位环境中，`int`和`long int`的最大值都是`2147483647`

在C90中，无后缀十进制整数通常会一次尝试`int`、`long int`、`unsigned long int`。而由于`2147483648`放不进前两个类型，所以最终会成为无符号类型，所以后续对它使用负号时，即`0 - 2147483648`这个式子，我们按照无符号处理时，我们后面得到的还是$-2147483648+2^{32} = 2147483648$，还是无符号。所以我们最后得到的就是`2147483648 < 2147483647`，结果为`false`

而到了C99，标准正式加入了`long long int`，无后缀十进制整数常量可以继续尝试`long long int`，而`2147483648`完全能够被64位`long long`表示，所以它可以成为有符号的`long long int`，而此时再加上负号，那就是真的`-2147483648`，没有回旋的余地，即此时是`-2147483648 < 2147483647`，结果为`true`

因此，C90和C99在这里真正变化的并不是`<`运算，而是`2147483648`这个整数字面量本身的类型不同，所以这也能解释为什么`-2147483647-1 < 2147483647`即使在前面的C90环境中仍然可以得到true。因为`2147483647`本身可以被`int`表示，再减1得到`-2147483648`，整个过程并没有把一个过大的正整数字面量先变成无符号类型

所以看起来同样是`-2147483648`，在C语言中却可能因为表达式形成过程不同而拥有完全不同的类型

我们再补充一点，无符号整数的溢出/下溢环绕是C语言定义好的行为，而有符号整数算术超过表示范围时通常属于 undefined behavior（未定义行为）

#### 2.3.4 通常算术转换怎样选择共同类型

前面说不能死记“只要有 unsigned 就全转 unsigned”，那么对于整数，判断顺序可以再具体一点：先做整数提升；两边符号性相同，转成等级较高的类型；符号性不同，则比较等级和表示范围。

- 无符号类型的等级不低于有符号类型时，转成无符号类型。
- 有符号类型等级更高，而且能表示无符号类型的全部值时，转成这个有符号类型。
- 否则，两边转成该有符号类型所对应的无符号类型。

比方说，在 LP64 Linux 中，64 位 `long` 能覆盖 32 位 `unsigned int` 的全部值，因此 `-1L < 1U` 为真；若 `long` 只有 32 位，转换路径就可能不同。这也是为什么判断表达式前，要先交代数据模型。

整数常量同样需要选择类型。C99～C17 中，无后缀十进制常量依次尝试 `int`、`long`、`long long`；无后缀八进制和十六进制常量还会在候选中穿插相应无符号类型。所以在 32 位 `int` 环境中，`0x80000000` 通常可以是 `unsigned int`，而十进制的 `2147483648` 会继续寻找能容纳它的有符号类型，不能只看两者的数学值相等就认定类型也相同。

#### 2.3.5 从关系表达式到数组下标

有了前面的转换规则，我们就能逐个判断下面这些关系表达式。下表采用 32 位 `int`，超出 `int` 范围的无符号值按 GCC/x86 的补码实现解释。

| 表达式 | 比较时的类型 | 结果 |
| --- | --- | --- |
| `0 == 0U` | `unsigned int` | 1 |
| `-1 < 0` | `int` | 1 |
| `-1 < 0U` | `unsigned int` | 0 |
| `2147483647 > -2147483647-1` | `int` | 1 |
| `2147483647U > -2147483647-1` | `unsigned int` | 0 |
| `2147483647 > (int)2147483648U` | `int` | 1 |
| `-1 > -2` | `int` | 1 |
| `(unsigned)-1 > -2` | `unsigned int` | 1 |

这种转换还会影响循环条件。比方说，现在有这样一段求和代码：

```c
int sum(int a[], unsigned len){
    int i, sum = 0;
    for(i = 0; i <= len - 1; i++)
        sum += a[i];
    return sum;
}
```

当 `len=0` 时，`len-1` 按无符号整数计算，得到 `UINT_MAX`，并不是 -1。接着比较时 `i` 又转成无符号数，于是循环会进入，访问数组范围之外的位置，程序可能报段错误。不能把段错误当成每次都保证出现的结果，越界访问本身已经属于未定义行为。

可以把循环条件改成 `i < len`，并让索引也使用 `unsigned`；若用它表示数组长度，更常见的写法是统一使用 `size_t`。这里假设数组元素求和不会超出 `int` 范围。

判断前面的 C90/C99 字面量问题时，还要同时检查 `int`、`long` 的宽度。64 位 Linux 的 `long` 通常已经能放下 2147483648，与 32 位 `long` 的情况不同。编译选项可以明确指定 `-std=c90` 或 `-std=c99`，但仅改变语言标准不会把数据模型变成 32 位。

在 x86-64 WSL 中运行这几个表达式，就能看到下面的结果。这里 `int` 是 4 字节，`long` 是 8 字节。`len=0` 时原来的循环条件仍为真；为了只观察转换，程序没有继续执行越界访问。下面给出可复制的程序，以及 VS Code 集成终端中使用 WSL 实际运行的结果截图，环境为 GCC 13.3.0、GDB 15.1，后面的运行记录也采用相同环境。


```c

int main(void){
  int neg=-1, zero=0; unsigned uzero=0;
  unsigned len=0; int i=0;
  printf("sizeof(int) = %zu, sizeof(long) = %zu\n",sizeof(int),sizeof(long));
  printf("-1 < 0           : %d\n",neg<zero);
  printf("-1 < 0U          : %d\n",neg<uzero);
```

## 3. 浮点数的表示

前面已经把浮点数理解成二进制的科学计数法。下面按照课本的顺序，先看一般浮点格式怎样决定范围，再讲规格化和 IEEE 754。为了避免把实际的阶和存进去的阶码混在一起，先约定几个符号：

| 符号 | 含义                    | 英文                             |
| ---- | ----------------------- | -------------------------------- |
| S    | 符号位                  | Sign                             |
| M    | 完整尾数 / 有效数       | Mantissa / Significand           |
| e    | 实际阶                  | Exponent                         |
| R    | 基数                    | Radix                            |
| E    | 机器中保存的阶码字段    | Exponent Field / Biased Exponent |
| f    | IEEE 754 保存的尾数字段 | Fraction                         |

### 3.1 浮点数的表示范围

定点数的小数点位置固定，在总位数有限时，很难同时照顾特别大和特别小的数。比方说，$9\times10^{-28}$ 和 $2\times10^{33}$，如果都按同一个固定比例保存，就需要很多位。

浮点数把有效数字和阶分开保存，一般写成 $N=(-1)^S\times M\times R^e$。二进制格式中，基数 R 通常固定为 2，不必另占空间；S 决定正负，M 保存有效数字，e 决定放大或缩小多少。如果阶采用偏置表示，机器中保存的是 $E=e+Bias$，读数时再用 $e=E-Bias$ 还原。

因此，在总位数一定时，多分一些位给阶码，可以扩大数量级范围；多分一些位给尾数，可以提高精度。**范围有多大和能保存多少有效位，是两个不同的问题。**

#### 3.1.1 从尾数和阶的边界计算范围

先不套用 IEEE 754。假设规格化尾数采用 $0.1\cdots$ 的形式，有 p 位有效数字，实际阶范围是 $e_{min}\sim e_{max}$。正数中，最小值要同时取最小尾数和最小阶，最大值则同时取最大尾数和最大阶：

| 边界 | 尾数 | 实际阶 | 真值 |
| --- | --- | --- | --- |
| 最小正规格化数 | $0.10\cdots0_2=1/2$ | $e_{min}$ | $2^{e_{min}-1}$ |
| 最大正规格化数 | $0.11\cdots1_2=1-2^{-p}$ | $e_{max}$ | $(1-2^{-p})2^{e_{max}}$ |

教材例 2.21 用了一个自定义的 32 位格式：1 位符号、8 位阶码、23 位尾数字段；尾数写成 $0.1\cdots$，最高位的 1 隐藏，所以一共有 24 位有效数字；阶码偏置为 128，实际阶范围是 -128～127。

代进去，它的最小正规格化数为 $2^{-129}$，最大正规格化数为 $(1-2^{-24})2^{127}$。负数范围关于 0 对称。只考虑这种规格化格式时，靠近 0 的一段非零数无法表示，绝对值太大的数也无法表示，分别对应下溢区和上溢区。

#### 3.1.2 同一个数，格式不同，机器数也不同

继续看教材的 65798。先转换为二进制：$65798=10000000100000110_2=0.10000000100000110_2\times2^{17}$。

按刚才的自定义格式，S=0，实际阶 e=17，阶码 $E=17+128=145=10010001_2$。尾数最高位的 1 不保存，剩下的位补齐到 23 位后，与符号、阶码组合，得到机器数 `48808300H`。

但这**不是 IEEE 754 单精度格式**。IEEE 754 的规格化尾数写成 $1.f$，偏置是 127。65798 要改写成 $1.0000000100000110_2\times2^{16}$，此时 e=16，E=143，机器数为 `47808300H`。虽然两种格式都是 32 位，也都按“1+8+23”分字段，解释规则不同，编码仍然不同。

所以，看一个浮点机器数之前，要先知道尾数的小数点在哪里、有没有隐藏位、阶码怎样编码，不能只凭字段位数就认定它是 `float`。

对于采用 $1.f$、有 p 位有效数字的二进制规格化数，在给定实际阶 e 时，相邻数的间隔是 $2^{e-(p-1)}$。阶增大 1，间隔也扩大一倍。也就是说，浮点数在数轴上并不等距：靠近 0 时密，绝对值较大时疏。

### 3.2 浮点数的规格化

**为什么浮点数需要规格化呢？**

现在看这几种写法：$0.001101_2\times2^6$、$0.01101_2\times2^5$、$0.1101_2\times2^4$，它们表示的是同一个数。但第一种写法的尾数前面有两个 0，白白占了位置，没有提供有效信息。我们希望有效数字尽量占满尾数，同时让同一个数按统一形式表示，于是就需要规格化。

上一节的教材例子把正尾数写成 $0.1xxxx_2$，规格化后满足 $1/2\le M<1$。小数点后第一位必须是 1，所以 $0.101101_2$ 是规格化尾数，$0.001011_2$ 则还要继续左移。


不过IEEE 754使用的是另一种更常见的写法，它的普通浮点数通常需要写成$1.xxxxx_2 \times 2^e$

比如，$1100.11_2$要把小数点移动到第一个非零数字后面，于是有$1.10011_2 \times 2^3$，因为小数点向左移动了3位，因此e = 3，即$1100.11_2 = 1.10011_2\times2^3$

对于小数点移动规律，我们利用拉马努金注意法就能注意到：

- 向左移动n位 $\Rightarrow$ $\times2^n$

- 向右移动n位 $\Rightarrow$ $\times2^{-n}$

比如，$0.00101_2$ 规格化后得到 $1.01_2\times2^{-3}$。因为小数点向右移动了3位，所以指数为 $-3$

对于 IEEE 754 的二进制规格化数，最高有效位总是 `1`，形式就是 `1.xxxxx`。既然每个规格化数都有这个 1，就没必要反复保存：存的时候省掉，读取和计算时再补回来，相当于省出一位存储空间。

例如，$1.10011_2$ 真正存入尾数字段的是 `10011`，前面的 1 称为隐藏位。这里说的是 IEEE 754 的规格化数；后面讲的非规格化数，隐藏位按 0 处理。

因此，IEEE 754 的 `float` 虽然只有23位尾数字段，但加上隐藏的最高位1后，实际上具有24位二进制有效数字；同理，`double` 实际具有53位二进制有效数字

在浮点运算过程中，结果还可能需要重新规格化。若结果的最高有效位没有处在规定位置，就需要将有效数字左移，同时阶减1，这称为**左规**；每左移一位，阶减1。反过来，如果运算结果出现类似 $10.xxxx_2$ 的形式，则需要将有效数字右移，同时阶加1，这称为**右规**

### 3.3 IEEE 754 浮点数标准

一般浮点格式可以自行约定尾数、阶码和偏置，但不同机器要交换数据，就需要统一这些规则。IEEE 754 规定了浮点数各字段的宽度和解释方式，也规定了零、无穷大、NaN 与非规格化数等情况。现代计算机中的浮点数主要采用这套标准。

我们最常见的有两种格式：

- 32 位单精度 `float`
- 64 位双精度 `double`

IEEE 754 浮点数仍然可以看成三部分：`S + E + f`，即**符号位 + 阶码字段 + 尾数字段**

[**注**]：这个标准是由IEEE（Institute of Electrical and Electronics Engineers）制定的，所以叫IEEE，至于754并没有什么特殊含义，只是刚好分配到这个标准编号罢了。还有一点，我们日常将“IEEE 754”读成“I triple E 754”，因为triple是三的意思，三个E


对于 IEEE 754 二进制规格化数，有$N=(-1)^S\times M\times R^e$，$M=(1.f)_2$，$e=E-Bias$这三个式子，我们统一出最终plus式子：
$$
N=(-1)^S\times(1.f)_2\times2^{E-Bias}
$$

#### 3.3.2 阶与阶码

前面已经区分了实际阶 e 和阶码 E。这里结合 IEEE 754 的偏置，看看它们怎样相互转换。

例如，$1.10011_2\times2^3$中，这里e = 3，这个3是实际阶，但是计算机并不会把这个3直接存进去，因为真正的指数既可能为正，也可能为负。当然我们也可以考虑用补码来保存指数，但是IEEE 754选择了另一种方案：偏置表示。它的思想非常简单，就是给所有指数统一加一个固定值，让原来的负指数也变成非负整数，这个还蛮像物理中的摄氏度和开尔文温度之间通过加上一个固定值进行转换，反正就是人为地给一条数轴整体平移

如果阶码字段一共有k位，则IEEE 754的偏置值为$Bias = 2^{k-1}-1$，于是$E=e+Bias$，反过来，也有$e=E-Bias$

对于float，$Bias = 2^{8-1}-1 = 127$，所以$E = e+127$，假设e = 3，那么运算过后，E = 130，转换成二进制，得到$10000010_2$，这就是真正的指数3对于float的阶码字段

当然，对于double，它的偏置值是1023，同理我们也能算出3对于double的阶码字段

总结一下，对于 IEEE 754 规格化数，有：

- float：阶 + 127$\Rightarrow$ 阶码，阶码 - 127$\Rightarrow$ 阶，$x=(-1)^S\times(1.f)_2\times2^{E-127}$
- double：阶 + 1023$\Rightarrow$ 阶码，阶码 - 1023$\Rightarrow$ 阶，$x=(-1)^S\times(1.f)_2\times2^{E-1023}$

这里的 `f` 是机器中真正保存的尾数字段，而规格化数真正参与计算的有效数为 $(1.f)_2$，因此对于规格化数，有 $M=(1.f)_2$

![实际阶加偏置127得到单精度阶码](/images/posts/computer-systems/lab03/lab03-09-biased-exponent.png)

#### 3.3.3 真值 $\Rightarrow$ IEEE 754 机器数

我们的统一流程为“十进制 $\rightarrow$ 二进制 $\rightarrow$ 规格化 $\rightarrow$ 符号位 $\rightarrow$ 阶码 $\rightarrow$ 尾数 $\rightarrow$ 机器码”

比方说，现在`float x = -12.75`，我们的操作流程如下：

1. 十进制 $\rightarrow$ 二进制

   整数部分，注意到$12_{10} = 1100_2$

   小数部分，注意到$0.75_{10} = 0.11_2$

   易得，$-12.75 = -1100.11_2$

2. 规格化

   $-1100.11_2 = -1.10011_2\times2^3$

   易得，e = 3

3. 符号位

   易得，S = 1

4. 阶码

   $E = 3+127=130 = 10000010_2$

5. 尾数

   由于规格化结果为$1.10011_2$，最高位的1为隐藏位，因此真正存入尾数字段的是$f = 10011$，补全23位后，有$f = 10011000000000000000000$

6. 组合

   $S=1$ ，$E=10000010$ ，$f=10011000000000000000000$

   得到完整二进制机器数 $11000001010011000000000000000000$，当然，这确实不是人看的~~（是神人看的）~~，所以我们要转换成十六进制

   先按照每4位分一组，$1100\ 0001\ 0100\ 1100\ 0000\ 0000\ 0000\ 0000$，再转换，得到$C14C0000_H$

![负十二点七五拆分为单精度浮点数的符号、阶码和尾数](/images/posts/computer-systems/lab03/lab03-03-ieee754.png)

#### 3.3.4 IEEE 754 机器数 $\Rightarrow$ 真值

把机器数还原成真值，就是把刚才的步骤倒过来。不过第一步要先确认它属于规格化数、非规格化数，还是特殊值。下面先看一个规格化单精度数。

反过来，我们的统一流程为“机器码 $\rightarrow$ 二进制 $\rightarrow$ 拆S/E/f $\rightarrow$ 求符号位 $\rightarrow$ 求实际阶 $\rightarrow$ 恢复有效数 $\rightarrow$ 求真值”

比方说，现在有$BEE00000_H$，我们的操作流程如下：

1. 转二进制

   $1011\ 1110\ 1110\ 0000\ 0000\ 0000\ 0000\ 0000$

2. 拆S/E/f

   按照float的"1+8+23"，拆成$1\ |\ 01111101 \ | \ 11000000000000000000000$

3. 求符号位

   S = 1，所以为负数

4. 求实际阶

   $E=01111101_2$

   转换为十进制后得到$E = 125$，根据公式得到$e = E-127 = -2$

5. 恢复有效数

   由$1100\dots$，补回隐藏位后，得到$1.11_2$，位权展开后得到$1.11_2 = 1.75_{10}$（当然，不展开也没关系，我们在下一步把小数点往前面移动也可以）

6. 求真值

   $x=(-1)^S\times1.75\times2^{-2}=-0.4375$

#### 3.3.5 特殊值、表示范围与上下溢

对于 `float`，8 位阶码共有 256 种编码，但并不全部用于普通规格化数。`00000000` 和 `11111111` 这一对难兄难弟，被留下来表示特殊情况。因此普通规格化数的阶码范围是 $1\le E\le254$；`double` 则是 $1\le E\le2046$。

读机器数时，先看阶码，再看尾数字段：

| 阶码 E | 尾数字段 f | 表示什么 | 有效数怎样恢复 |
| --- | --- | --- | --- |
| 全 0 | 全 0 | +0 或 -0，由符号位决定 | 0 |
| 全 0 | 非 0 | 非规格化数，也叫次正规数 | $(0.f)_2$ |
| 非全 0 且非全 1 | 任意 | 规格化数 | $(1.f)_2$ |
| 全 1 | 全 0 | 正无穷或负无穷，由符号位决定 | 不套普通数值公式 |
| 全 1 | 非 0 | NaN，Not a Number | 不套普通数值公式 |

NaN 用来表示没有正常数值意义的结果，比如默认 IEEE 754 环境中的 `0.0/0.0`。~~注意这里不是氮化钠，氮化钠是 $Na_3N$，不是 NaN（bushi）~~

**非规格化数有两个地方一起变：隐藏位由 1 变成 0，实际阶则固定在普通规格化数的最小阶。** 对单精度，公式是 $x=(-1)^S\times(0.f)_2\times2^{-126}$；对双精度，则是 $x=(-1)^S\times(0.f)_2\times2^{-1022}$。不能看到 E=0，就仍然拿 E 减偏置，再补上隐藏的 1。

比方说，单精度 `00000001H` 的尾数字段只有最后一位为 1，所以有效数是 $2^{-23}$，整个数为 $2^{-23}\times2^{-126}=2^{-149}$。实际阶没有降到 -149，变小的是尾数。

这样就能把几个边界算出来：

| 边界 | 单精度 `float` | 双精度 `double` |
| --- | --- | --- |
| 最小正规格化数 | $2^{-126}$ | $2^{-1022}$ |
| 最小正非零数 | $2^{-149}$ | $2^{-1074}$ |
| 最大有限正数 | $(2-2^{-23})2^{127}$ | $(2-2^{-52})2^{1023}$ |

第一行取最小普通阶码和有效数 1；第二行取全 0 阶码与最小的非零尾数字段；第三行取最大普通阶码与全 1 尾数字段。因此，最小正规格化数并不是能表示的最小正数。

非规格化数把规格化区间和 0 接了起来。单精度最大的正非规格化数 `007FFFFFH` 为 $(1-2^{-23})2^{-126}$，紧接着的 `00800000H` 为 $2^{-126}$，两者只差 $2^{-149}$。这就是**渐进下溢**：数越来越小时，还能借助非规格化数继续逼近 0。

![阶码为零时隐藏位由一变为零以表示非规格化数](/images/posts/computer-systems/lab03/lab03-10-subnormal.png)

再看上溢和下溢。**上溢**指结果绝对值太大，规格化并舍入后，所需的阶超出格式能够表示的范围。尾数暂时变成 `10.xxxx` 不一定上溢，它还可以右移一位、阶加 1；要看调整后是否仍能表示。

**下溢**则与接近 0 的小数有关。当非零结果小到普通规格化数放不下时，可以先用非规格化数表示；更小时，再按舍入规则得到最接近的可表示数，也可能得到 0。这里沿用教材对范围的直观说明；严格说，IEEE 754 的下溢异常还涉及结果是否微小且不精确，精确的非规格化结果不一定触发下溢异常。

+0 和 -0 的位模式不同，但普通数值比较认为它们相等。符号仍可能影响后续运算：在默认 IEEE 754 环境中，`1.0/(+0.0)` 与 `1.0/(-0.0)` 分别得到正无穷和负无穷。NaN 则与任何数作 `==` 比较都为假，包括它自己，检测时应使用 `isnan`。

### 3.4 C 语言中的浮点数类型

C 语言提供 `float`、`double` 和 `long double`。前面讨论的 x86/Linux 环境中，前两者对应 IEEE 754 单精度和双精度；`long double` 的格式和占用空间需要看具体 ABI，不能直接认定它就是 128 位精度。

`1.1` 默认是 `double` 常量，`1.1f` 才是 `float` 常量，`1.1L` 对应 `long double`。`float` 传给 `printf` 时会提升为 `double`，而 `scanf` 中 `%f` 接收 `float*`，`%lf` 接收 `double*`，这两处不要混用。

整数转换成浮点数，范围足够也可能损失有效位；`float` 转成 `double` 能保留原来的值，但不能恢复之前已经丢失的精度。有限浮点数转成整数时向零截断，截断后的值若超出目标整数类型范围，则不能当成普通的取模转换。

教材还介绍了扩展精度：例如 x87 的 80 位扩展格式使用显式的整数位，并不是把双精度原样加长几个字节。因此，要区分一个类型占用的存储空间与格式中实际用于表示数值的位数，不能看到 `sizeof(long double)` 就直接推出它有多少位精度。

#### 3.4.1 类型转换与精度

浮点数能表示的范围很大，但有效位数仍然有限。单精度加上隐藏位只有 24 位二进制有效数字，双精度为 53 位。一个值落在它的范围内，并不意味着就能精确保存。

比方说，前面已经算过，0.1 转成二进制后会无限循环。机器只能保存有限位，所以在默认就近舍入下，实际保存的是最接近 0.1 的可表示值。整数也会遇到类似问题：单精度可以精确保存 $2^{24}$，却不能精确保存 $2^{24}+1$，因为这个范围内相邻数的间隔已经是 2。

教材例 2.24 就用类型转换说明这个区别。假设 `i` 是 32 位 `int`，`f`、`d` 分别是有限的 `float`、`double` 值。下面只讨论转换在目标类型范围内的情况，尤其不能让浮点转 `int` 的结果越界：

| 表达式 | 是否总成立 | 原因 |
| --- | --- | --- |
| `i == (int)(float)i` | 否 | 转成 `float` 时可能丢失整数低位 |
| `f == (float)(int)f` | 否 | 转成 `int` 时会丢掉小数部分 |
| `i == (int)(double)i` | 是 | 双精度的 53 位有效数字足以精确保存 32 位 `int` |
| `f == (float)(double)f` | 是 | 双精度能精确保存单精度已有的值 |
| `d == (float)d` | 否 | 即使仍在单精度范围内，也可能损失有效位 |
| `f == -(-f)` | 是 | 对有限值，两次取反恢复原值 |
| `(d + f) - d == f` | 否 | 相加时较小的数可能因舍入而丢失 |

这里尤其要注意往返转换：先把 `int` 转成 `float`，再转回 `int`，不会把已经丢失的低位找回来；先把 `float` 扩展成 `double`，也只是精确保留原来的近似值，不会重新得到输入时的数学真值。

大致来讲，`float`通常提供约7位的十进制有效数字，`double`通常能够提供约15~16位的十进制有效数字

#### 3.4.2 从底层表示看 float 和 double 的精度

不能只用“输出了几位小数”来判断精度，因为 `printf` 可以补出很多位，这不代表那些位都是可靠的有效数字。可以先用 `<float.h>` 检查当前实现，再观察一个无法精确表示的小数。

```c
#include <stdio.h>
#include <float.h>

int main(void){
  float a=0.1f; double b=0.1;
  volatile float x=-0x1p25f,y=0x1p25f,z=1.0f;
  volatile float xy=x+y,yz=y+z;
  printf("FLT_RADIX = %d\n",FLT_RADIX);
  printf("float : %d binary digits; %d guaranteed decimal digits\n",FLT_MANT_DIG,FLT_DIG);
  printf("double: %d binary digits; %d guaranteed decimal digits\n",DBL_MANT_DIG,DBL_DIG);
  printf("0.1f  = %.20f\n",(double)a);
  printf("0.1   = %.20f\n",b);
  printf("(x+y)+z = %.1f\n",(double)(xy+z));
  printf("x+(y+z) = %.1f\n",(double)(x+yz));

 return 0;
}
```

在二进制单、双精度实现中，`FLT_MANT_DIG`、`DBL_MANT_DIG` 分别为 24、53，而 `FLT_DIG`、`DBL_DIG` 通常为 6、15。这里 6 和 15 指保证的十进制有效位数；前面说“约 7 位”和“约 15～16 位”是对二进制精度的近似换算，两者的口径不同。

还可以逐次将变量中的步长减半，观察 `1 + 步长` 何时舍入回 1。在按目标类型精度保存中间值、采用就近舍入时，它能帮助理解 1 附近相邻可表示数的间隔，但测到的不是整个浮点范围内固定不变的绝对间隔。

在机器中实际保存并打印这两个 `0.1`，可以看到 `float` 和 `double` 各自的近似值。把每一步结果按单精度保存后，`(x+y)+z` 得到 1，而 `x+(y+z)` 得到 0，后面浮点运算部分会继续解释这个差异。

## 4. 非数值数据的编码表示

### 4.1 逻辑值

有时我们不把一串 bit 看成一个整数，而是把每一位看成独立的逻辑值。例如一个字节可以记录 8 个开关的状态，每一位的 0/1 分别表示关/开。

这里还要区分“每一位表示一个逻辑值”和 C 语言的真假判断。C 的条件表达式把 0 看成假、非 0 看成真，逻辑运算的结果则为 0 或 1；`_Bool` 保存的也是 0 或 1。

从硬件看，一个 n 位寄存器可以保存 n 个独立的真假状态；从 C 对象看，一个 `_Bool` 通常仍会占用至少一个可寻址字节，并不是声明了一个布尔变量就只占一个 bit。如果希望在一个字节中保存多个状态，就需要后面要讲的掩码和按位运算。

### 4.2 西文字符

ASCII 用 7 位二进制给 128 个字符编码，也就是 0～127，存储时通常放在一个 8 位字节中，最高位为 0。前面说过，`char` 本身属于整数类型；当我们用它保存字符时，存进去的仍然是字符对应的编码值。比方说，`A` 的编码是 65，把它按数字打印是 65，按字符输出则显示 A。

| 字符 | ASCII 十六进制编码 |
| --- | --- |
| `'0'` | `30` |
| `'A'` | `41` |
| `'a'` | `61` |
| `'@'` | `40` |
| `'\0'` | `00` |

比方说，字符 `'0'` 的编码是 48，不是整数 0；数字字符转数值可以用 `c - '0'`。ASCII 大小写英文字母相差 `0x20`，但这个规律针对英文字母，不能对所有字符一律加减 32。

ASCII 的 `'0'～'9'` 连续编码为 `0x30～0x39`，`'A'～'Z'`、`'a'～'z'` 也各自连续。比方说 `'7'-'0'=7`，得到的才是整数值 7；反过来，整数 7 加上 `'0'` 就得到字符 `'7'` 的编码。

ASCII 中还有不直接显示字形的控制字符，如换行 `\n`、回车 `\r`、制表 `\t`。C 字符串以值为 0 的空字符 `\0` 结束，字符 `'0'` 的值却是 `0x30`，两者不能混淆。

数组 `char a[] = "ABC";` 实际保存 `41 42 43 00` 共 4 个字节，`strlen(a)` 为 3，`sizeof(a)` 为 4。字符串的空字符属于对象存储的一部分，只是不计入字符串长度。

字符串就是把这些字符字节依次排在内存中。每个字节已经有先后次序，不会因为机器的大小端而反转。比方说，使用 2.2 节已经定义的 `show_bytes`，可以这样查看：

```c
const char *s = "abcdef";
show_bytes(s, strlen(s));
```

在常见的 ASCII 兼容环境中，会输出`61 62 63 64 65 66`

这是因为字符串由一个个字符字节按顺序组成，`strlen(s)` 返回字符串长度 `6`，不包含结尾的空字符 `\0`，所以这里不会打印最后的 `00`

另外，`strlen(s)` 和 `sizeof(s)` 不是一回事：在这段代码中，`s` 是指针，因此 `sizeof(s)` 得到的是指针大小；`strlen(s)` 才是字符串中空字符之前的字符数量。如果直接对字符串数组使用 `sizeof`，结果又可能不同

![字符串ABC在内存中保存三个字符编码与一个空字符](/images/posts/computer-systems/lab03/lab03-11-ascii-string.png)

### 4.3 汉字字符

汉字也需要用数字编码，但它涉及的不只是“存什么数”：从键盘输入，到系统内部保存，再到屏幕上画出字形，分别需要不同的规则。教材因此区分了输入码、机内码和字形表示。

| 名称 | 解决什么问题 | 例子 |
| --- | --- | --- |
| 输入码（外码） | 怎样从键盘输入汉字 | 拼音、五笔 |
| 内码 | 汉字在系统中怎样存储和交换 | GB2312 相关编码、UTF-8 等 |
| 字模点阵码或轮廓描述 | 汉字最后怎样画出来 | 点阵、字体中的轮廓 |

教材介绍的 GB2312 收录了 6763 个汉字和 687 个非汉字图形字符，采用 94×94 的编码表。表中每个字符都有区号和位号，合起来叫区位码。区位码的两个分量分别加 `0x20` 得到国标交换码；在教材讨论的兼容 ASCII 的双字节机内码中，再分别设置最高位。

比方说，“大”的区号是 20，位号是 83，写成十六进制分量是 `14 53`，国标码是 `34 73`，对应的机内码是 `B4 F3`。区号 20 是十进制，不能直接当成 `0x20` 使用。

当然，不能据此记成“汉字一定占两个字节”。Unicode 为字符分配码点，UTF-8 则把码点编码成字节序列；常见汉字在 UTF-8 中通常占 3 字节，也有需要 4 字节的汉字。所以 `strlen` 数的是字节，不是我们眼睛看到的汉字个数。字形又由字体决定，更换字体并不等于更换字符编码。

## 5. 数据的宽度和存储

### 5.1 数据的宽度和单位

| 名称 | 含义 |
| ---- | ---- |
| bit（位） | 二进制信息的最小单位，只能是 `0` 或 `1` |
| byte（字节） | 常见计算机中 `1 byte = 8 bit` |
| word（字） | 计算机处理数据时使用的一个单位，具体宽度取决于体系结构 |
| word size（字长） | 通常用来描述处理器内部整数运算通路、寄存器等的宽度，反映处理器一次处理数据的能力 |

注意，“字”和“字长”不一定完全相同。比如，Intel x86 体系结构历史上把 16 位称为 word、32 位称为 double word、64 位称为 quad word；而 GDB 的内存查看命令中，`w` 固定表示 4 字节，不能直接把它理解成任何处理器上的“字长”

下面列出常见的 32 位系统，以及采用LP64（Long and Pointer 64）数据模型的 Linux x86-64 系统中的典型情况

| C 数据类型 | 常见 32 位系统 | 常见 Linux x86-64（LP64） |
| ---------- | -------------: | ------------------------: |
| `char` | 1 字节 | 1 字节 |
| `short` | 2 字节 | 2 字节 |
| `int` | 4 字节 | 4 字节 |
| `long` | 4 字节 | 8 字节 |
| `long long` | 8 字节 | 8 字节 |
| `float` | 4 字节 | 4 字节 |
| `double` | 8 字节 | 8 字节 |
| 对象指针，例如 `int *`、`void *` | 4 字节 | 8 字节 |

这张表也说明，64 位系统并不意味着每种整数类型都变成 64 位

当然，有两点需要注意：

1. 这张表是常见平台的典型情况，不是说 C 语言规定所有平台都必须采用这些大小。尤其是 `long`、指针和 `long double`，会受到平台、编译器和 ABI 的影响
2. C 语言规定 `sizeof(char)` 的结果一定是 `1`，但严格来说，一个 C 的 byte 不一定在所有特殊平台上都等于 8 bit；我们日常使用的 x86/Linux 环境中，一个 byte 通常就是 8 bit

不过，我们也完全可以通过`sizeof`来检查当前环境

```c
#include <stdio.h>
#include <limits.h>

int main(void){
    printf("CHAR_BIT = %d\n",CHAR_BIT);
    printf("sizeof(char) = %zu\n",sizeof(char));
    printf("sizeof(short) = %zu\n",sizeof(short));
    printf("sizeof(int) = %zu\n",sizeof(int));
    printf("sizeof(long) = %zu\n",sizeof(long));
    printf("sizeof(long long) = %zu\n",sizeof(long long));
    printf("sizeof(float) = %zu\n",sizeof(float));
    printf("sizeof(double) = %zu\n",sizeof(double));
    printf("sizeof(void *) = %zu\n",sizeof(void *));

    return 0;
}
```

其中，`sizeof` 返回的是**字节数**，`%zu` 是用于输出 `size_t` 类型的格式说明符，`CHAR_BIT` 则表示一个 byte 包含多少个 bit

额外的，我们稍微补充一下存储容量单位的知识：

| 单位 | 二进制换算 |
| ---- | ---------- |
| KB | $2^{10}$ 字节 = 1,024 字节 |
| MB | $2^{20}$ 字节 = 1,048,576 字节 |
| GB | $2^{30}$ 字节 |
| TB | $2^{40}$ 字节 |
| PB | $2^{50}$ 字节 |
| EB | $2^{60}$ 字节 |

[**注**]：这里要留意单位约定，我们这里采用的是 1 KB = 1,024 字节的换算方式，而在有些地方中 KB 也可能按十进制定义为 1,000 字节，当然 KiB 则明确表示 1,024 字节

大写 B 常表示 byte，小写 b 常表示 bit，因此 8 Mb 的数据量对应 1 MB，不能把 Mb/s 与 MB/s 直接当成同一个速度单位。网络和设备的标称速率常按十进制换算，比方说 100 Mb/s 对应理论上的 12.5 MB/s，实际有效传输速度还受协议开销等因素影响。

若采用二进制容量词头，1 KiB 为 $2^{10}$ B，1 MiB 为 $2^{20}$ B，1 GiB 为 $2^{30}$ B；十进制的 kB、MB、GB 分别对应 $10^3$、$10^6$、$10^9$ B。教材里沿用 KB 等表示二进制容量时，要根据上下文读，不要把两个口径混着计算。

### 5.2 数据的存储和排列顺序

#### 5.2.1 内存地址与内容

现代计算机通常采用**按字节编址**的方式，也就是说，每个内存地址对应一个字节。一个变量如果占用多个字节，就会占据一段连续的内存地址

假设现在有一个四个字节的`int`变量，`int x = 0x12345678;`，我们让变量 `x` 从地址 `0x1000` 开始存放，那么它会占用 `0x1000`、`0x1001`、`0x1002`、`0x1003` 这四个地址。每个地址里放的是一个字节，而不是整个 `int`

在大一上我们学c语言的时候，也许有不少同学对指针和地址的内容有点困惑，而为了使我后续的讲解更加易懂，所以下面我会先做一些区分：

| 写法 | 含义 |
| ---- | ---- |
| `x` | 变量 `x` 的值，也就是按 `int` 类型解释后的数值 |
| `&x` | 变量 `x` 的地址 |
| `p`，其中 `int* p = &x;` | 指针变量 `p` 保存的地址，即 `x` 的地址 |
| `*p` | 访问指针 `p` 指向的对象，也就是 `x` 的内容 |
| `&p` | 指针变量 `p` 自己存放在内存中的地址 |

这里一定要分清，地址和地址里面的内容不是一回事。`&x` 是地址，`x` 是变量的值；`p` 保存一个地址，而 `*p` 才是这个地址指向的内容

这也解释了为什么 GDB 中的 `p/x &x` 和 `x/xw &x` 含义不同：前者打印变量地址，后者从这个地址开始读取内存内容

[**注**]：因为对于c语言，`int *x`和`int* x`来说都是一样的，所以我一般来说会规范一下：如果要声明一个指针，我会把`*`给前面这个类型，也就是`int* x`，而如果我要用这个指针的值，那我才会`*x`。也就是说，一个重心在前面这个类型声明，一个重心在后面这个指针本身

#### 5.2.2 字节序：大端与小端

这两个缩写会在后续会反复出现，但要注意它们有时指“位”，有时指“字节”，需要结合上下文理解

| 缩写 | 英文 | 含义 |
| ---- | ---- | ---- |
| LSB | Least Significant Bit / Byte | 最低有效位 / 最低有效字节 |
| MSB | Most Significant Bit / Byte | 最高有效位 / 最高有效字节 |

例如，32 位二进制数 `00000000 00000000 00000000 00000101` 中，最右侧的 `1` 是最低有效位；如果把它按字节分成 `00 00 00 05`，那么 `05` 是最低有效字节，最左侧的 `00` 是最高有效字节

对于带符号补码整数，最高有效位通常也是符号位：最高位为 `0` 表示非负数，最高位为 `1` 表示负数。但讨论大小端时，MSB 通常指**最高有效字节**，不是单独的最高有效位

多字节数据会占用连续的多个字节。不同机器的区别在于：这些字节在内存中的排列顺序可能不同，这就是字节序（Endian）

假设变量 `value` 是一个 4 字节整数，数值为 `0x12345678`，那么我们会有

| 地址递增方向 | 小端方式（Little-endian） | 大端方式（Big-endian） |
| ------------ | ------------------------ | ---------------------- |
| 低地址 | `0x78` | `0x12` |
| 低地址 + 1 | `0x56` | `0x34` |
| 低地址 + 2 | `0x34` | `0x56` |
| 高地址 | `0x12` | `0x78` |

- **小端方式**：最低有效字节 LSB 放在低地址，最高有效字节 MSB 放在高地址
- **大端方式**：最高有效字节 MSB 放在低地址，最低有效字节 LSB 放在高地址


为了方便记忆，我们可以记“小端就是小对小大对大，大端正好相反”

但是，此时就有人要问了，大小端会不会改变变量的数值

在同一台机器上，执行 `printf("%x", (unsigned int)value)`，如果 `value` 是 `0x12345678`，通常仍然会输出 `12345678`。大小端影响的是这个值的字节如何放在内存里，不是程序中这个整数本身的数值
还要注意，大小端讨论的是多字节数据中各字节的排列顺序，不是把每个字节内部的 8 个 bit 反过来排列。单字节对象没有字节顺序上的区别，因此字符串中的字符字节不会因为机器是大端或小端就被反转

![整数0x12345678在小端与大端机器上的字节排列](/images/posts/computer-systems/lab03/lab03-04-endianness.png)

对 `unsigned int x = 0x12345678;`，在小端机器上从 `&x` 开始逐字节读到 `78 56 34 12`，但一次按 4 字节整数读取时，又会按本机字节序重新组合成 `0x12345678`。因此同一份内存，用不同的读取单位显示，看到的排列形式可能不同。

对象地址指向它占用的最低地址字节，而不是永远指向“最高有效字节”。指针加法也要看类型：`unsigned char*` 加 1 前进一个字节，`int*` 加 1 前进 `sizeof(int)` 个字节，不能因为地址都用十六进制打印，就忽略它们的步长区别。

跨机器传递一个整数的原始字节时，双方还需要约定字节序和数据宽度；直接复制本机的几个字节，并不能自动让另一种布局的机器正确读出原值。

#### 5.2.3 从低地址的字节判断大小端

对于用c语言查看大小端，最直接的方法是把一个整数的地址转换为 `unsigned char *`，然后观察它的第一个字节，因为C 语言允许通过字符类型的指针查看对象表示中的字节

```c
#include <stdio.h>

int main(void)
{
    unsigned int value = 1;
    unsigned char *p = (unsigned char *)&value;

    if(p[0] == 1)
        printf("Little-endian\n");
    else if(p[0] == 0)
        printf("Big-endian\n");
    else
        printf("Unknown byte order\n");

    return 0;
}
```

运行原理：`value` 的数值是 `1`，在常见的 32 位整数表示中，它的二进制形式为 `00 00 00 01`

- 小端方式：低地址先放最低有效字节，所以 `p[0]` 为 `1`
- 大端方式：低地址先放最高有效字节，所以 `p[0]` 为 `0`


在常见的 x86-64 Linux/WSL 环境中，通常会输出 `Little-endian`

我们还可以使用 `union` 检查字节序，因为联合体的所有成员从同一个起始地址开始存放，因此也可以先写入整数，再查看它的第一个字节：

```c
#include <stdio.h>

union ByteOrder{
    unsigned int value;
    unsigned char bytes[sizeof(unsigned int)];
};

int main(void){
    union ByteOrder data;
    data.value = 1;

    if(data.bytes[0] == 1)
        printf("Little-endian\n");
    else if(data.bytes[0] == 0)
        printf("Big-endian\n");
    else
        printf("Unknown byte order\n");

    return 0;
}
```

两种方法的核心原理是一样的：先给一个多字节对象写入已知数值，再观察低地址处的字节。

教材例 2.26 还提醒了一个容易误判的地方：如果联合体里用的是普通 `char`，并把整数改成 `0xFF`，再判断第一个字节是否等于 `0xFF`，在普通 `char` 有符号的小端环境中，结果反而可能为假。

原因并不是字节序变了。低地址确实放着 `FF`，但按有符号 `char` 读出来是 -1；比较时它先提升为 `int`，仍是 -1，而常量 `0xFF` 的值是 255，所以两者不相等。上面的代码明确使用 `unsigned char`，读到 `FF` 就是 255，也就避免了这个问题。前面讲过的整数提升，在看内存时同样会起作用。

#### 5.2.4 用 show_bytes 观察对象表示

前面在 2.2 节写过通用的 `show_bytes`。原笔记中的另一版代码采用同样的做法，只是把字符指针另外起名为 `byte_pointer`，并写了几个函数分别查看整数、浮点数和指针。下面沿用原来的命名，对照各次调用读到了哪些字节。


代码中定义了`typedef unsigned char *byte_pointer;`，`byte_pointer` 是 `unsigned char *` 的别名。由于 `unsigned char` 每次表示一个字节，所以 `start[i]` 可以依次访问从起始地址开始的各个字节

| 函数 | 功能 |
| ---- | ---- |
| `show_bytes(start, len)` | 从 `start` 开始，按地址递增顺序打印 `len` 个字节，每个字节用两位十六进制显示 |
| `show_int(x)` | 查看 `int` 类型参数的字节表示，长度为 `sizeof(int)` |
| `show_float(x)` | 查看 `float` 类型参数的字节表示，长度为 `sizeof(float)` |
| `show_pointer(x)` | 查看指针值本身的字节表示，长度为 `sizeof(void *)` |
| `test_show_bytes(val)` | 建立一个 `int`、将它转换为 `float`，再建立一个指向该整数的指针，依次显示三者的字节 |
| `simple_show_a()` | 对 `0x87654321` 分别显示前 1、2、3 个字节 |
| `simple_show_b()` | 对 `0x12345678` 分别显示前 1、2、3 个字节 |
| `float_eg()` | 对比 `3490593`、`3510593` 的整数表示和浮点数表示 |
| `string_ueg()`、`string_leg()` | 分别显示字符串 `ABCDEF`、`abcdef` 中各字符的字节 |
| `show_twocomp()` | 显示 `short` 类型的 `12345` 和 `-12345` 的字节表示 |

`show_bytes` 的核心逻辑如下。这里给 `start[i]` 显式转换为 `unsigned int`，是为了让它与 `%x` 的参数类型相匹配，写法更严谨

```c
void show_bytes(byte_pointer start,int len){
    int i;

    for(i = 0;i < len;++i)
        printf(" %.2x",(unsigned int)start[i]);

    printf("\n");
}
```

注意，`show_bytes(valp, 2)` 每次都是从 `valp` 指向的**起始地址**重新开始打印两个字节，并不是接着上一次输出的位置继续打印


先看 `simple_show_a()`。在本文 GCC 环境中，`int val = 0x87654321;` 会保留这 32 位编码；这个十六进制常量超出 32 位 `int` 的正数范围，赋给 `int` 的结果依赖实现。下面只观察它的字节，不把这种赋值推广到所有平台。

从低地址开始读取时，会有：

| 调用 | 小端输出 | 大端输出 |
| ---- | -------- | -------- |
| `show_bytes(valp, 1)` | `21` | `87` |
| `show_bytes(valp, 2)` | `21 43` | `87 65` |
| `show_bytes(valp, 3)` | `21 43 65` | `87 65 43` |

对于 `int val = 0x12345678;`，结果则是：

| 调用 | 小端输出 | 大端输出 |
| ---- | -------- | -------- |
| `show_bytes(valp, 1)` | `78` | `12` |
| `show_bytes(valp, 2)` | `78 56` | `12 34` |
| `show_bytes(valp, 3)` | `78 56 34` | `12 34 56` |

这两组结果正好体现了大小端的定义。`show_bytes` 只负责从低地址向高地址读字节，所以具体打印顺序取决于这些字节原本在内存中的排列顺序


接着看 `test_show_bytes`。它不只查看一个整数，还把这个整数转换成 `float`，并查看指针本身：

```c
int ival = val;
float fval = (float)ival;
int *pval = &ival;

show_int(ival);
show_float(fval);
show_pointer(pval);
```

- `show_int(ival)` 显示整数 `ival` 自身的字节
- `show_float(fval)` 显示转换后的浮点数 `fval` 自身的字节。这里的转换是数值转换，不是把 `ival` 的字节原封不动复制成 `float`
- `show_pointer(pval)` 显示指针 `pval` 保存的地址值的字节，而不是直接显示 `ival` 的内容

`show_pointer` 的输出和运行时地址有关，因此每次运行、不同编译选项或不同系统下都可能不同。64 位环境中的普通对象指针通常占 8 字节，32 位环境中通常占 4 字节；应该通过 `sizeof(void *)` 或 `sizeof(pval)` 检查，而不是把某次运行的地址写死


字符串的字节示例已经放在 4.2 节，那里也说明了 `strlen` 与 `sizeof` 的区别。

#### 5.2.5 用 GDB 读取内存中的机器数

除了在 C 程序中逐字节读取，也可以让 GDB 直接查看变量的内存。这时不需要改动变量，只需把断点停在初始化完成之后，再指定起始地址、读取长度和显示格式。

GDB可以使用`x`命令查看变量在内存中的机器表示，基本格式为`x /nfu <addr>`

把这个命令拆开看：

| 符号 | 含义               | 全称    |
| ---- | ------------------ | ------- |
| x    | 查看内存           | examine |

| f    | 显示格式           | format  |
| u    | 每个内存单元的长度 | unit    |

| 格式 | 含义         |
| ---- | ------------ |
| x    | 十六进制     |
| d    | 有符号十进制 |
| u    | 无符号十进制 |
| t    | 二进制       |
| f    | 浮点数       |

例如，`x /xw &x` 按十六进制显示，`x /tw &x` 按二进制显示。u 则决定每个读取单元有多少字节：

| 标记 | 大小  | 全称       |

| b    | 1字节 | byte       |

| 变量 | 完整机器数（十六进制） |
| --- | --- |

比方说，$-32768$ 的 32 位补码是 $2^{32}-32768$；$522=512+10=020A_H$；$10.5=1.0101_2\times2^3$，双精度阶码为 $3+1023=1026$。`-1.1f` 的二进制小数不能有限表示，需要对尾数舍入。

如果希望把浮点数的位模式按符号位、阶码和尾数字段输出，可以通过 `memcpy` 把 `float` 的位模式复制到同样宽度的 `uint32_t`，再从第 31 位到第 0 位输出。这里是复制对象表示，不能写成 `(uint32_t)a`，后者是数值转换。下面采用 32 位 `uint32_t` 和 IEEE 754 单精度 `float`，两者使用相容的字节序，这与常见 x86/Linux 环境一致。

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>

int main(void){
    float a = -1.1f;
    uint32_t bits;
    if(sizeof(a) != sizeof(bits))
        return 1;
    memcpy(&bits, &a, sizeof(bits));
    for(int i = 31; i >= 0; --i){
        putchar(((bits >> i) & 1U) ? '1' : '0');
        if(i == 31 || i == 23)
            putchar(' ');
    }
    putchar('\n');
    return 0;
}
```

按 C99 或之后的标准编译，预期输出为 `1 01111111 00011001100110011001101`，正好对应 `BF8CCCCD`。这是一项根据格式计算的预期结果，实际调试时再与本机输出对照。

同一个整数转换成无符号类型前后的值，也可以用 `int i = -1;` 和 `printf("%d %u\n", i, (unsigned)i);` 对照。这里改变的是数值的类型；上面的 `memcpy` 则是在复制位模式，两种操作要分清。

把本节几种观察方式放到一起，最后再区分一下：

| 容易混淆的内容 | 正确理解 |
| -------------- | -------- |
| 完整机器数与 `show_bytes` 输出 | `0x12345678` 是完整 32 位机器数的写法；小端内存从低地址输出时是 `78 56 34 12`。 |
| 数值转换与重新解释位模式 | `(float)ival` 是把整数数值转换成浮点数；它不是把整数的 32 个 bit 原样复制成 `float`。 |
| 大小端与内存对齐 | 大小端决定多字节对象的字节排列顺序；对齐决定对象或成员从哪个地址开始存放。 |
| `struct` 与 `union` | `struct` 的成员分别占用空间，可能产生填充；`union` 的成员共享同一段存储空间。 |
| `sizeof` 与 `strlen` | `sizeof` 计算对象或类型的大小；`strlen` 计算 C 字符串中 `\0` 之前的字节数。 |
| 变量值与变量地址 | `x` 是变量的值，`&x` 是变量地址；GDB 的 `p/x &x` 看地址，`x/4xb &x` 看该地址开始的 4 个字节。 |

### 5.3 结构体、联合体与数据对齐

前面研究了一个数据内部的字节怎样排列，下面继续看多个成员怎样分别占用或共享存储空间，以及它们从哪个地址开始存放。大小端决定字节的排列顺序，对齐则决定对象或成员的起始位置。

为了提高内存访问效率，编译器通常会让变量从满足一定倍数要求的地址开始存放。

| 类型 | 对齐要求 |
| ---- | -------------------- |
| `char` | 任意地址 |
| `short` | 地址是 2 的倍数 |
| `int` | 地址是 4 的倍数 |
| `long`（典型 32 位环境） | 地址是 4 的倍数 |
| `float` | 地址是 4 的倍数 |
| `double` | 地址是 8 的倍数 |

这里的对齐要求会受到具体体系结构、编译器和 ABI 的影响，所以不要把这张表当作所有平台的硬性规则

下面结构体中的成员间填充和尾部填充，就是为了满足这些对齐要求。若要在自己的环境中检查布局，可以使用 `sizeof`、C11 的 `_Alignof` 和 `<stddef.h>` 中的 `offsetof`，分别查看对象大小、对齐要求和成员偏移。

#### 5.3.1 结构体数据的分配和访问

我们先看结构体的成员怎样排列

结构体的成员按照声明顺序排列，但编译器可能在成员之间插入填充字节（padding），使后面的成员满足对齐要求。结构体末尾也可能有尾部填充，以保证数组中下一个结构体对象仍然满足对齐要求

```c
struct StructData
{
    char a;
    int b;
    short c;
    char d;
};

struct StructData2
{
    char a;
    char d;
    short c;
    int b;
};
```

这里，在 `char` 按 1 字节、`short` 按 2 字节、`int` 按 4 字节对齐的常见环境中，第一个结构体的布局如下

| 偏移量 | 内容 | 占用字节 | 原因 |
| ------ | ---- | -------: | ---- |
| 0 | `a` | 1 | `char` 可从任意地址开始 |
| 1～3 | 填充 | 3 | 让 `b` 从 4 的倍数地址开始 |
| 4～7 | `b` | 4 | `int` 占 4 字节 |
| 8～9 | `c` | 2 | `short` 占 2 字节 |
| 10 | `d` | 1 | `char` 占 1 字节 |
| 11 | 尾部填充 | 1 | 让结构体大小成为 4 的倍数 |

因此`sizeof(struct StructData) = 12`

虽然成员本身总共只占 `1 + 4 + 2 + 1 = 8` 字节，但结构体还包含 3 个成员间填充字节和 1 个尾部填充字节，所以最终大小是 12 字节

第二个结构体调整了成员顺序

| 偏移量 | 内容 | 占用字节 |
| ------ | ---- | -------: |
| 0 | `a` | 1 |
| 1 | `d` | 1 |
| 2～3 | `c` | 2 |
| 4～7 | `b` | 4 |

因此，在相同的典型对齐规则下`sizeof(struct StructData2) = 8`

这说明成员顺序可能影响结构体大小。一般来说，在不影响程序语义的前提下，把对齐要求较大的成员放在前面，有时可以减少填充空间，不过具体布局最好还是以当前编译器和平台为准

![调整成员顺序将结构体从12字节缩减到8字节](/images/posts/computer-systems/lab03/lab03-05-struct-alignment.png)

用 `offsetof`、`sizeof` 和逐字节输出检查这两个结构体，当前环境得到的偏移与前面的布局一致。输出同时给出了整数的低地址字节和 `ABC` 后面的 `00`，可以把大小端、结构体布局与字符串存储联系起来看。

把下面的代码保存为 `layout.c`：

```c

#include <stdlib.h>
#include <limits.h>
#include <float.h>
#include <stddef.h>
#include <stdint.h>
#include <string.h>
struct A { char a; int b; short c; char d; };
struct B { char a; char d; short c; int b; };
static void bytes(const void *p, size_t n){
 const unsigned char *b=p;
 for(size_t i=0;i<n;i++) printf(" %02x",(unsigned)b[i]);
```

#### 5.3.2 联合体数据的分配和访问

`union` 中文常叫联合体或共用体。它和 `struct` 最大的区别是

- `struct` 的成员各自占有自己的存储空间，成员同时存在
- `union` 的所有成员共享同一段存储空间，成员的起始地址相同


例如

```c
union UnionData
{
    char a;
    int b;
    short c;
    char d;
};
```

在 `int` 占 4 字节、对齐要求为 4 的常见环境中，最大的成员是 `int b`，因此`sizeof(union UnionData) = 4`

所有成员都从联合体起始地址开始，写入 `b` 后，再查看 `a`，实际上就是把同一段内存的第一个字节按 `char` 类型解释。在小端机器上，如果 `b = 100`，`int` 的机器数是 `0x00000064`，内存低地址处通常是 `0x64`，它对应 ASCII 字符 `'d'`

不过，`union` 不应被当成通用的数值类型转换工具。通过不同成员解释同一段内存时，结果会受到数据表示、字节序和平台规则影响

我们可以简单整理下

| 对比项 | `struct` | `union` |
| ------ | -------- | ------- |
| 成员存储 | 各成员分别存储 | 所有成员共享同一段空间 |
| 成员起始地址 | 按布局和对齐规则确定，通常不同 | 所有成员起始地址相同 |
| 大小 | 成员大小之和再加上必要的填充 | 至少能容纳最大成员，并满足整体对齐要求 |
| 典型用途 | 同时保存一个对象的多个字段 | 在不同表示之间共享一段存储空间 |

严格来说，联合体大小不一定永远等于最大成员大小；编译器还要满足联合体的整体对齐要求

## 6. 数据的基本运算

前面研究的是数据怎样表示，下面再看这些 bit 怎样参加运算。机器位宽有限，所以数学上的结果、机器保留的位模式和 C 语言允许的行为需要分开看。

### 6.1 按位运算和逻辑运算

| 运算 | C 运算符 | 含义 |
| --- | --- | --- |
| 按位与 | `&` | 对应位都为 1，结果才为 1 |
| 按位或 | `\|` | 对应位有一个为 1，结果就为 1 |
| 按位异或 | `^` | 对应位不同为 1，相同为 0 |
| 按位取反 | `~` | 每一位翻转 |
| 逻辑与、或、非 | `&&`、`\|\|`、`!` | 先按整体判断真假，结果为 0 或 1 |

比方说，`0x0f & 0x33` 得到 `0x03`，而 `0x0f && 0x33` 得到 1。`&&`、`||` 还会短路：左边已经能决定结果时，右边就不再求值。

用无符号整数操作位更直观。若第 k 位的掩码为 `1U << k`，则 `x & mask` 用于检查该位，`x | mask` 用于置 1，`x & ~mask` 用于清 0，`x ^ mask` 用于翻转。这里 k 必须小于 `unsigned int` 的位宽。

比方说，`x & 0xffU` 保留最低 8 位，`(x >> 8) & 0xffU` 先右移再提取第 8～15 位。假设 x 是 32 位无符号数，这样就能按字段拆出某个字节。

这里判断某一位是否为 1，应该写 `(x & mask) != 0`，而不是一般性地写 `(x & mask) == 1`，因为第 3 位的掩码是 8，提取结果可能是 8 而不是 1。多个位是否全部置 1，可以检查 `(x & mask) == mask`。

另外，`~` 是对提升后操作数的所有位取反。32 位 `int` 环境中，`~0x0fU` 是 `0xfffffff0`；如果只想查看 8 位内的取反结果，还要再与 `0xffU` 相与，不能凭书写了两位十六进制就假定运算宽度只有 8 位。

![掩码0x0F保留0x8C的低四位得到0x0C](/images/posts/computer-systems/lab03/lab03-12-bit-mask.png)

### 6.2 左移和右移运算

左移把低位空位补 0，高位移出；逻辑右移把高位补 0，算术右移把高位补符号位。比如把 8 位模式 `11111000` 右移两位，逻辑右移得到 `00111110`，算术右移得到 `11111110`。

C 中无符号数右移是逻辑右移；负的有符号数右移，在本课常用的 GCC/x86 环境中采用算术右移，但 C90～C17 下属于实现定义行为。移位前还要考虑整数提升，移位量不能为负，也不能达到或超过提升后左操作数的位宽。负的有符号数左移以及超出相应规则的有符号左移，不能直接当作普通乘法使用。

下面只看固定的 8 位位模式，暂不涉及 C 的整数提升。

| 原位模式 | 操作 | 结果 | 解释 |
| --- | --- | --- | --- |
| `00101100` | 左移 2 位 | `10110000` | 无符号值 44 变成 176；按补码解释则已超出正数范围 |
| `11111000` | 逻辑右移 2 位 | `00111110` | 无符号值 248 除以 4 得 62 |
| `11111000` | 算术右移 2 位 | `11111110` | 补码值 -8 除以 4 得 -2 |
| `11111001` | 算术右移 2 位 | `11111110` | -7 向负无穷取整得到 -2，不等于向零截断的 -1 |

左移会丢高位，右移会丢低位，所以一左一右不一定恢复原数。移位要看丢掉的是什么、空位怎样补，以及结果还是否落在所采用的数值范围内。

![相同八位模式逻辑右移补零算术右移补符号](/images/posts/computer-systems/lab03/lab03-13-right-shift.png)

在当前 GCC/x86-64 环境中，负数右移采用算术右移。下面可以直接看到 `-7 >> 2` 与 `-7 / 4` 的结果不同；先加偏移量 3 再右移，结果才与向零截断一致。

把下面的代码保存为 `shift.c`：

```c
#include <stdio.h>

int main(void){
  unsigned int u=248U;int v=-8,w=-7;
  printf("unsigned 248 >> 2 = %u\n",u>>2);
  printf("signed    -8 >> 2 = %d\n",v>>2);
  printf("signed    -7 >> 2 = %d\n",w>>2);
  printf("signed    -7 / 4  = %d\n",w/4);
  printf("(-7 + 3) >> 2     = %d\n",(w+3)>>2);
  printf("0x8c & 0x0f       = 0x%02x\n",0x8cU&0x0fU);
  puts("Signed right shift: observed GCC/x86-64 behavior.");

 return 0;
}
```

### 6.3 位扩展和位截断运算

前面讲整数转换时提到过扩展和截断，这里再看它们为什么会保留或改变真值。

| 操作 | 做法 | 例子 |
| --- | --- | --- |
| 零扩展 | 高位补 0 | `11111001` → `00000000 11111001`，无符号值仍为 249 |
| 符号扩展 | 高位补符号位 | `11111001` → `11111111 11111001`，补码值仍为 -7 |
| 位截断 | 只保留低 k 位 | `00000001 11111001` → `11111001` |

截断后按无符号数解释，相当于对 $2^k$ 取模；按补码解释，还要根据保留下来的最高位重新判断符号。C 中转成无符号类型的取模规则是明确的，超范围转成有符号类型时则要看所采用的语言标准和实现，不能只凭“截掉就行”概括所有转换。

假设一个 n 位补码负数对应的无符号值为 U，真值是 $U-2^n$。把它符号扩展到 m 位，高处增加的全 1 部分值为 $2^m-2^n$，新编码的无符号值就变成 $U'=U+2^m-2^n$。

按 m 位补码解释：

$$
U'-2^m=U+2^m-2^n-2^m=U-2^n
$$

所以真值不变。反过来，如果对负数补 0，最高位会变成 0，原来的负数就会变成大正数。比方说，`11111001` 零扩展为 `00000000 11111001` 是 249，符号扩展为 `11111111 11111001` 才是 -7。

而截断会改变哪一位担当符号位。例如 `00000000 10000000` 原来是 128，截成 8 位后得到 `10000000`，若按补码解释就成了 -128。截断后再扩展，也不能恢复已经丢失的信息。

### 6.4 整数加减运算

前面讲补码时说过，它能把减法变成加法。现在把这件事放到硬件里看：加法器把两个位串相加；做减法时，先把减数逐位取反，再在最低位加 1，就可以交给同一个加法器计算。因此，**无符号整数和补码整数的加减，可以共用一套加减运算电路。**

再往后看，整数乘法可以借助移位和累加实现，除法也可以借助移位、比较与加减实现，加法器因此是算术运算的重要基础。但这不等于所有运算都只经过一个加法器：按位逻辑运算需要相应逻辑电路，处理器也可以设置专门的乘法器、除法器和浮点运算部件。

固定 n 位加法器只保留结果低 n 位，最高位之外的进位不再属于结果，所以结果位模式相当于对 $2^n$ 取模。补码减法可以写成 $A-B=A+(-B)$，这也是前面补数法的用途。

无符号加法若产生最高位之外的进位，说明精确结果超出范围；补码加法则看两个同号数相加，结果是否变成异号。两个异号补码整数相加不会发生有符号加法溢出。

比方说，8 位模式 `01111111 + 00000001 = 10000000`，按补码解释就从 127 变成 -128，发生有符号溢出；按无符号解释，127+1=128，并没有溢出。可见进位和有符号溢出不是一回事。

[**注**]：这里的 8 位例子描述的是固定位宽硬件。C 的 `char`、`short` 通常先提升成 `int` 再运算；C 中有符号算术溢出属于未定义行为，不能因为硬件会保留低位，就认定源程序一定按这种方式环绕。

#### 6.4.1 加减运算器怎样共用加法器

用 Sub 表示加减控制信号，让 Y 的每一位都与 Sub 异或，同时把 Sub 接到最低位进位输入，那么运算器就可以计算

$$
R=X+(Y\oplus\{n\text{ 个 Sub}\})+Sub\pmod{2^n}
$$

Sub=0 时，Y 不变，计算 X+Y；Sub=1 时，Y 全部取反，再加 1，计算 X-Y。这也是补码能让加法器完成减法的电路形式。

同样的电路可以处理无符号和补码加减，结果位模式相同，区别在于怎样解释结果和判断越界。x86 加减指令会更新若干标志，其中这几个最常用：

| 标志 | 含义 | 主要看什么 |
| --- | --- | --- |
| CF | 进位/借位标志 | 无符号加法是否进位，减法是否借位 |
| OF | 有符号溢出标志 | 补码精确结果是否超出表示范围 |
| SF | 符号标志 | 结果最高位是否为 1 |
| ZF | 零标志 | 结果各位是否全为 0 |

对于加法，若加法器最高位向外进位为 C，则 CF=C。减法采用取反加一时，x86 的借位标志 CF 与最后进位相反，所以可以写成 $CF=Sub\oplus C$。OF 可由符号位的输入进位与输出进位异或得到。SF 直接取结果最高位，ZF 在结果全 0 时为 1。

教材例 2.27 中的求和程序，就是前面 2.3 节的 `i <= len - 1`。`len=0` 时，若 len 是无符号类型，`len-1` 得到最大无符号数，比较采用无符号规则，循环错误地进入。教材把 len 改成 `int` 后，0-1 得到 -1，再按有符号规则比较，循环就不进入了。

从 x86 指令来看，减法和比较都可以由同样的减法运算产生标志，但无符号大小关系主要看 CF、ZF，有符号大小关系则结合 SF、OF、ZF 判断。因此源码里只改一个类型，就可能改变后续条件跳转。也可以像前文那样用无符号长度与 `i < len`，关键是让条件符合所采用的类型规则。

#### 6.4.2 用同一组机器数看无符号与补码结果

机器数写成十六进制后，**可以直接按十六进制加减，不必每次都展开成二进制。** 规则和十进制竖式一样，只不过从“满十进一、借一当十”变成了“满十六进一、借一当十六”。

比方说，`86H + F6H`：个位的 6+6=12，写成十六进制是 C；高一位的 8+F=23，写成十六进制是 17，所以完整的和为 `17CH`。若只保留 8 位，也就是两位十六进制数，结果就是 `7CH`，最高处的 1 是进位。

减法同理。`10H - 01H` 的个位不够减，就向高位借 1；借来的 1 相当于 16，所以个位得到 F，高位剩下 0，结果为 `0FH`。

十六进制只是机器数的简写，并没有改变位宽或运算规则。算出保留结果以后，还要分别判断无符号和补码意义下是否溢出。下面以刚才的 8 位加法为例：

| 项目 | 二进制 | 十六进制 |
| --- | --- | --- |
| X | `10000110` | `86H` |
| Y | `11110110` | `F6H` |
| 完整和 | `1 01111100` | `17CH` |
| 保留低 8 位 | `01111100` | `7CH` |

结果保留 `7CH`。按无符号解释，$134+246=380$，超过 255，保留低 8 位后是 124；按补码解释，$-122+(-10)=-132$，小于 -128，同样只留下 124。这里 CF=1、OF=1、SF=0、ZF=0。

但二者不总是一起置位。`7FH + 01H = 80H` 时，无符号结果 128 正常，CF=0；补码结果超出范围，OF=1。`FFH + 01H = 00H` 时，CF=1，但按补码解释是 -1+1=0，OF=0。

把加法、减法的判断方法放在一起，可以记这个口诀：

- **无符号：最高位加法有进位，减法有借位，就溢出。**
- **有符号：同号相加得异号；异号相减，结果与减数同号，就溢出。**

这里的“最高位有进位”指的是向位宽以外进位，不是内部任意一位进位；“借位”则是被减数不够减，需要向位宽以外借位。比方说，8 位的 `0FH + 01H = 10H` 只是内部进位，没有超过 `FFH`，所以没有无符号溢出；`FFH + 01H` 才会向第 9 位进位。无符号减法中，`00H - 01H` 不够减，保留结果为 `FFH`，CF=1。

有符号的口诀说的是补码运算。比方说，8 位的 127+1，两个正数相加，结果位模式却是负数的 `80H`，OF=1；127-(-1) 则是异号相减，结果 `80H` 与减数 -1 都是负号，OF=1。“与减数同号”也就等价于“与被减数异号”。异号相加不会发生有符号加法溢出，同号相减也不会发生有符号减法溢出。

| 8 位运算 | 保留结果 | CF | OF | SF | ZF |
| --- | --- | --- | --- | --- | --- |
| `7FH + 01H` | `80H` | 0 | 1 | 1 | 0 |
| `FFH + 01H` | `00H` | 1 | 0 | 0 | 1 |
| `86H + F6H` | `7CH` | 1 | 1 | 0 | 0 |
| `00H - 01H` | `FFH` | 1 | 0 | 1 | 0 |
| `7FH - FFH` | `80H` | 1 | 1 | 1 | 0 |

所以，**无符号溢出看 CF，有符号溢出看 OF；SF 只记录结果最高位，ZF 只记录结果是否为零。** SF=1 并不等于发生有符号溢出，CF=1 也不能代替 OF。

上面都是固定位宽硬件的计算与判断，不是在让 C 程序先执行有符号溢出再检查。因此也不能总用“先算 x-y，再看是否小于 0”替代比较；差本身可能已经超出有符号类型的范围。

### 6.5 整数乘除运算

两个 n 位整数的完整乘积最多需要 2n 位，若只保留 n 位，高位可能被截掉。无符号乘法按目标无符号类型取模，有符号乘法则仍需避免溢出。

#### 6.5.1 完整乘积与低位乘积

同一组 n 位位模式，按无符号数相乘和按补码数相乘，完整的 2n 位结果可能不同，但是低 n 位相同。这是因为两种解释的操作数相差 $2^n$ 的整数倍，乘积对 $2^n$ 取模后没有区别。

比方说，4 位 `1101` 和 `1110` 按无符号解释为 13、14，完整乘积为 `10110110`；按补码解释为 -3、-2，完整乘积为 `00000110`。它们低 4 位都是 `0110`，但是高 4 位不同。所以不能拿无符号完整乘积的高位，直接判断补码乘法是否溢出。

| 乘法类型 | 保留低 n 位时，怎样判断完整乘积能否放下 |
| --- | --- |
| 无符号乘法 | 高 n 位必须全为 0 |
| 补码乘法 | 真正的 2n 位补码乘积，高 n 位必须全部等于低 n 位的符号位 |

例如，4 位补码的 -8×2 得到 8 位 `11110000`，低 4 位是 `0000`，高位不是它的符号扩展，发生溢出；-3×(-2) 得到 `00000110`，高位正好是低位的符号扩展，没有溢出。硬件可以采用 Booth 乘法等专门算法生成补码完整乘积，这里先掌握表示和判定规则。

#### 6.5.2 在计算前判断是否会溢出

对无符号整数 x、y，若结果类型上界为 M，则 `y != 0 && x > M / y` 表示乘积将超出范围。比如分配 count 个元素，每个元素占 size 个字节，计算 `count * size` 前应先确认乘法能放进 `size_t`，否则可能只申请到一小块空间，却按原来的 count 写入。

```c
/* count、size 均为 size_t，SIZE_MAX 来自 <stdint.h> */
if(size != 0 && count > SIZE_MAX / size){
    /* 无法用 size_t 表示所需字节数 */
}
```

教材例 2.31 给出的内存分配问题很直观：在 32 位大小计算的环境中，假设一个 `int` 占 4 字节，要申请 $2^{30}+1$ 个元素，数学上需要 $2^{32}+4$ 字节。但乘积只保留低 32 位后变成 4，实际只申请到一个元素的空间，后面却还按原来的数量写入，就会越界。本文的 64 位 `size_t` 不会在这个数上回绕，但同样需要在它自己的上界之前检查。

对于有符号整数，不应先让乘法溢出，再用结果除回去检查，因为溢出的那一步已经是未定义行为。若要扩大结果范围，要在乘法之前转换，例如在 32 位 `int` 环境中，`(long long)x * y` 先扩展再乘，而 `(long long)(x * y)` 已经来不及了。

从 C99 起，整数除法不能整除时向零截断，例如 `7/3=2`、`-7/3=-2`。余数满足 `a == (a/b)*b + a%b`，非零余数与被除数同号。除数为 0，以及最小有符号整数除以 -1 导致商无法表示，都是未定义行为。

### 6.6 常量的乘除运算

这里的“常量乘除”指的是乘数或除数在编译时已经确定，比如 `x * 20`、`x / 4`；x 本身仍然可以在运行时变化。

既然常量已经知道，编译器就可以提前选择另一种计算方法，用移位、加减等操作代替某些乘除。这是一种优化：在适合的处理器上，减少计算代价。不过，移位加减是否更快，要看处理器的指令和执行成本，不能把它记成“乘除一定慢，移位一定快”。

对于常量乘法，比方说 $20x=16x+4x$，可以对应两次左移再相加；$15x=16x-x$，则可以用左移和减法。但这些首先是数学上的等价式，手工写成 C 表达式时，仍要检查类型、移位和溢出规则。

无符号数除以 $2^k$ 可以用逻辑右移 k 位。负的补码数则需要留意：算术右移向负无穷方向取整，而 C99 整数除法向零截断。比如 -3 算术右移 1 位得到 -2，但 `-3/2` 得到 -1。

因此，在采用算术右移的环境中，若 $x<0$，可以先加偏移量 $2^k-1$，再右移 k 位，把结果修正为向零截断：

$$
\operatorname{trunc}(x/2^k)=\left\lfloor\frac{x+(2^k-1)}{2^k}\right\rfloor,\qquad x<0
$$

比方说，-7/4 应得 -1，直接算术右移两位得到 -2；先加 3 得到 -4，再右移两位才得到 -1。对于非负数，不需要加偏移。写成 C 表达式时，还要保证偏移量的类型、位宽和移位量都合适。

写程序时通常仍可以直接写 `x * 20`、`x / 4`，让编译器根据目标处理器选择指令。学习这些转换，是为了理解底层怎样计算、怎样优化，以及为什么有符号除法不能随手改成右移；并不是要求每次写乘除都手动展开。

其他常量的除法还可能被编译器转换为乘法和移位，不能把它们都简单记成右移。

### 6.7 浮点数运算

整数加法可以直接把同一位权的位相加，浮点数却不行：两个尾数虽然都写成 `1.xxxx`，实际阶可能不同，位权也就不同。因此，浮点加减要先对阶，再进行有效数加减，最后规格化、舍入并检查结果范围。乘除的步骤略有不同，放在后面讲。

#### 6.7.1 浮点加减与对阶

比方说，计算 $1.5+(-125.25)$。先把两者写成二进制规格化形式：

$$
1.5=1.1_2\times2^0,\qquad -125.25=-1.11110101_2\times2^6
$$

小阶向大阶看齐，1.5 的有效数右移 6 位，变成 $0.0000011_2\times2^6$，然后在相同的阶下相加：

$$
(0.00000110_2-1.11110101_2)\times2^6
=-1.11101111_2\times2^6
$$

结果已经规格化，真值为 -123.75。这个例子只有有限位二进制小数，单精度就能精确容纳，不需要丢弃有效位；若有效位超过保存能力，才需要按舍入规则处理。计算中必须把隐藏位还原回来，它没有存入字段，并不代表加减时也可以把它忽略。

![二进制浮点加法先对齐指数再相加有效数](/images/posts/computer-systems/lab03/lab03-14-floating-add.png)

#### 6.7.2 舍入与附加位

对阶和右规可能移出低位，为了正确决定最终舍入，可以保留保护位 G、舍入位 R 和粘位 S；粘位记录更低位中是否出现过 1。这里的 S 是 sticky，和前文的符号位 S 要根据上下文区分。

教材介绍的舍入方式有就近舍入到偶数、朝正无穷舍入、朝负无穷舍入和朝零舍入。默认常用的是就近舍入到偶数：选最近的可表示数，正好处在中点时，让保留结果的最低位为 0。它不是把所有中间值一律往上加 1。

设 L 是准备保留的最后一位，G 是它后面的保护位，R 是再后一位，S 是更低所有位的逻辑或。就近舍入到偶数时，可以按下面的规则决定是否给保留部分加 1：

$$
\text{进位条件}=G\land(R\lor S\lor L)
$$

G=0，说明小于半个末位单位，直接舍去；G=1 且 R 或 S 为 1，说明大于一半，要进位；G=1、R=S=0，正好处于中间，则看 L：L=0 就保持，L=1 就进位，使最终最低位为 0。

以只保留 4 位有效数为例，$1.0101_2$ 恰好在 $1.010_2$ 与 $1.011_2$ 中间，选末位为 0 的 $1.010_2$；$1.0111_2$ 则选 $1.100_2$。这就是“偶数”对应的具体一位，不是看十进制整数部分是奇数还是偶数。

舍入还可能让有效数从 `1.111...` 变成 `10.000...`，此时需要再右规，阶加 1，并重新检查是否上溢。可见规格化和舍入不是互不影响的两个动作。

#### 6.7.3 规格化与渐进下溢

以单精度为例，令 $x=1.1_2\times2^{-126}$、$y=1.0_2\times2^{-126}$，相减得到 $0.1_2\times2^{-126}=2^{-127}$。如果继续强行使用普通规格化数公式，就需要实际阶 -127，但普通规格化单精度最小阶为 -126。

因此结果转入非规格化表示：阶码全 0，尾数字段为 `100...0`，完整机器数为 `00400000H`。它的有效数是 `0.1`，仍使用 $2^{-126}$ 的缩放比例，正好表示 $2^{-127}$。这里是一个可精确表示的非规格化结果，不要把它直接丢成 0。

换一种情况，若相减得到 $0.1_2\times2^{-125}$，则可以左规成 $1.0_2\times2^{-126}$，恰好落在最小正规格化数 `00800000H`。两次结果看起来都需要左规，但能否保持普通规格化格式，要看调整后的实际阶是否仍在范围内。

#### 6.7.4 浮点乘除

浮点乘法把有效数相乘、实际阶相加；除法把有效数相除、实际阶相减，符号由两个操作数的符号决定。它们不需要像加减那样先对阶，但结果仍需要规格化、舍入和范围检查。

普通规格化数相乘时，实际阶相加；若直接使用保存的阶码，便有

$$
e_x+e_y=(E_x-Bias)+(E_y-Bias)
$$

因此在重新加回一次偏置后，初始结果阶码应为 $E_x+E_y-Bias$，随后再考虑规格化调整。相除时类似，初始结果阶码为 $E_x-E_y+Bias$。全 0 和全 1 阶码对应的特殊情况，需要先分类处理，不能直接套这两个式子。

比方说，$1.5\times1.5=1.1_2\times1.1_2=10.01_2$，尾数乘完后要右规成 $1.001_2\times2^1$。相乘前两个实际阶都为 0，右规以后结果实际阶才变成 1。

#### 6.7.5 精度误差与运算顺序

前面说过，精度有限会丢失低位。如果一个大数和一个很小的数相加，对阶后，较小数的有效位可能落到最终保留范围之外，整个贡献都被舍掉。

比方说，按单精度保存每一步结果，令 `x=-0x1p25f`、`y=0x1p25f`、`z=1.0f`。`(x+y)+z` 得到 1，而 `x+(y+z)` 中 `y+z` 舍入后仍是 y，所以得到 0。这里应采用通常的浮点求值规则，不能开启允许编译器重新结合表达式的优化来验证顺序。

误差还可能在重复计算中累积。教材例 2.35 用每 0.1 秒计一次数说明这个问题：0.1 的二进制小数不能有限表示，如果用 24 位定点小数保存它（1 位符号、23 位小数），并直接截断后面的位，每次换算时间时都会带入同一方向的误差。运行 100 小时后，时间误差约为 0.343 秒；若用它计算每秒飞行 2000 米的目标位置，距离误差就约为 687 米。

教材接着比较了舍入、单精度浮点表示和更宽的定点表示。这个例子说明，误差不仅取决于“是不是浮点数”，还取决于保留了多少有效位、采用截断还是舍入，以及后面怎样使用这个近似值。增加表示位数或改变舍入方法，都可能改变长期计算的结果。

最后，还要把浮点特殊值与整数异常分开。在默认不陷阱的 IEEE 754 环境中，非零有限数除以零会产生带符号无穷大，`0.0/0.0` 等无效运算会产生 NaN；整数除以零则是未定义行为，不能照搬浮点数的规则。

## 7. 本章小结

| 要处理的问题 | 需要先确定什么 | 常见混淆 |
| --- | --- | --- |
| 从位串求真值 | 位宽、编码、小数点位置 | 最高位为 1 就一律当负数 |
| 整数表达式比较 | 提升和通常算术转换后的共同类型 | 直接按数学上的正负比较 |
| 解码浮点数 | 阶码类别、偏置、隐藏位 | 把非规格化数也补上隐藏的 1 |
| 判断精度 | 有效位数与当前阶 | 小数点后打印位数等于可靠位数 |
| 读取内存 | 起始地址、读取长度、字节序 | 把地址与内容混为一谈 |
| 分析运算结果 | 精确结果、保留位模式、溢出规则 | 用硬件截断代替 C 语言语义 |

同一串 bit 可以有不同解释，先确定类型和编码，再谈真值。整数重点看补码、范围和类型转换；浮点数重点分清实际阶、阶码、隐藏位与舍入；查看内存时，再把完整机器数和按地址排列的字节对应起来。程序中的比较结果、精度误差和 GDB 输出，都可以沿着这几步分析。
